# 프로파일링과 Evidence

프로파일링은 [CHILL 스케줄러](README.md)가 구성 선택에 사용할 근거를 실측하는
과정이다. 측정 항목은 스케줄러가 내려야 할 결정에서 도출한다. 측정 기능이나
저장 형식을 먼저 고정하고 제어 목표를 거기에 맞추지 않는다.

## 측정의 단위

프로파일링과 Serving은 같은 firstfloor/backend 실행 경로를 사용한다. 하나의 측정 세션은
한 구성(노드, 모델, 실행 경로, 전력모드)을 측정한다. 세션은 대상 장비, 모델 산출물, 전처리 산출물,
데이터셋, firstfloor/backend 버전과 설정, 전력모드, 메모리와 가속기 조건, 런타임 기본 병렬성,
실행 배치 조건을 고정하고, 이 조건을 측정 결과와 함께 보존한다. Serving은 프로파일을 측정할 때 쓴
실행 이미지를 그대로 써서 준비하며, 이후 선언이 바뀌어도 측정한 이미지로 실행한다. 이미지는 운영자가
쓴 표기 그대로 다루고 형식을 강제하지 않는다. Serving이 실제로 프로파일과 같은 능력을 보이는지는
Serving 관측의 배치 실행시간과 노드 전력을 같은 조건의 프로파일과 대조해 확인한다.

프로파일은 측정한 노드의 것이다. 같은 기종의 다른 노드에 재사용하지 않고 노드마다 측정한다.
다른 기종과 장비 계열 사이의 일반화는 금지한다.

| 측정 | 실행 조건과 관측 |
|---|---|
| 고정 구성 프로파일링 | 한 구성마다 세션 하나를 ChillServer가 실행한다. 배치 크기마다 Serving의 준비 동작으로 고정 배치 인스턴스를 준비하고, Job이 Serving과 같은 Service 경로로 부하를 보내고, 인스턴스를 제거한다. 요청은 데이터셋의 프로파일링 부분집합에서 가져온다. 수준은 포화와 중간이며, 드문 도착 수준은 배치 크기 1에서만 둔다. 수준은 표본 수와 최소 전력 관측 시간을 채우거나 시간 한도에 닿으면 끝난다. 세션마다 부하 뒤 관측이 하나다. 배치 실행시간과 직전 유휴 간격의 기록, 디스패치 점유, 메모리, 노드 벽전력을 측정한다. 수준 구성은 측정 입력이다 |
| 모델 로드 유휴 측정 | 같은 firstfloor/backend, 모델과 자원 조건에서 요청을 처리하지 않는 상태의 소비를 측정. 정착 시간은 측정 입력이며, 부하 중단 뒤 노드 전력이 안정되는 시간을 근거로 정한다 |
| Serving 관측 | 실제 요청의 대기, 전달, 실행과 반환을 포함한 종단 지연과 처리 결과, 자원 사용과 Pod 변화와 장애 감지를 기록하고 원래 기록 그대로 API로 제공한다 |
| 디스패치 점유 측정 | 고정 배치 크기 인스턴스 하나에 그 처리율보다 많은 요청을 보낸 포화 구간에서 지속 처리율을 재고, 요청 하나가 배치 실행시간 밖에서 인스턴스를 점유하는 시간을 장비, 전력모드, runtime, 모델마다 산출. 포화 구간은 인스턴스가 다음 요청을 기다린 시간의 합이 측정 창 길이의 정해진 비율 이하인 구간이다. 연속 배치 쌍마다 `d=(다음 배치 시작−앞 배치 시작−앞 배치의 실제 실행시간)/B`로 계산하며, 앞 배치의 실제 실행시간이 없는 쌍은 쓰지 않는다 |

전환 측정은 출발 상태와 도착 상태, 실행한 동작을 함께 기록한다.

프로파일의 서비스 시간 기록은 배치 실행마다 하나이며 직전 유휴 간격과 짝이다. 직전 유휴 간격이 없는 기록은 버린다.
Serving 인스턴스와 세션 인스턴스는 쓸 모든 배치 크기를 준비 실행으로 워밍업하므로 어느 배치 크기에서도 첫 실행을 따로 구분하지 않는다.
서비스 시간 분위수는 질의한 직전 유휴 간격에 로그 거리로 가장 가까운 기록 N개의 경험적 분위수다.
N은 분위수가 정하는 표본 하한(`ceil(ln(1−p)/ln(p))`, 95분위는 59)이다.
기록이 N개보다 적은 배치 크기는 측정 없음으로 다루고, 100분위는 받지 않는다.
데이터셋의 프로파일링 부분집합과 평가 부하 부분집합은 서로 다른 표본으로 구성한다.

세션은 모든 배치 크기의 부하가 끝난 뒤 같은 모델 적재 인스턴스를 요청 없이 유지하며 전력을 관측한다.
이 관측은 유휴 전력과 유지 시간을 정하는 근거이며 수준의 입력당 에너지에 섞지 않는다.

### 측정 POOL

프로파일링과 전환 비용 측정은 측정 POOL의 노드에서만 수행한다. 측정을 요청하면
CHILL이 대상 노드를 측정 POOL로 옮기고, 측정이 끝나거나 실패하면 가용 노드로
돌려보낸다. 실패는 측정 결과로 기록한다. 활성 POOL에서 서빙 중인 노드에 대한 측정
요청은 거절하고 사유를 남긴다. CHILL이 배치하지 않은 파드가 측정 노드에 있어도 측정을
진행하고, 측정 구간에 있던 그 파드들의 목록을 결과와 함께 기록한다.
한 노드의 측정 요청은 요청 순서대로 하나씩 실행하고, 서로 다른 노드의 측정은 동시에
진행한다. 측정이 노드에 둔 파드는 서빙으로 보지 않는다. 요청이 가리키는 측정 근거를
쓸 수 없거나 메모리, GPU와 장치 신원과 소유권 조건을 충족하지 못하면 요청을 거절하고
사유를 남긴다. 온라인 CPU와 서빙 CPU 예약과 affinity를 실행 허가 조건으로 쓰지 않는다.

### 자원 할당과 측정 축

Profiling과 Serving을 포함한 모든 CHILL 연산은 CPU를 예약, 제한과 고정하지 않는
공유 실행을 사용한다. 장비와 전력모드별 CPU 동결표, request/limit/quota, 명시적
affinity/pinning 및 독점 코어 배정은 두지 않는다. CPU 생략을 양수 request나
allocatable 기반 quota와 전체 mask로 보충하지 않는다.

런타임 스레드는 quota와 분리하고 런타임 기본과 자동 병렬성을 따른다. 인스턴스별 실행은
한 번에 배치 하나이며 스레드 수와 동시 추론 수를 별도 탐색 축으로 두지 않는다.
실제 적용 thread 설정, cpuset/affinity, unlimited를 포함한 cgroup quota,
CPU 사용량과 throttling을 실행 사실로 기록한다.

가속기 할당과 장비 신원, 런타임, 전력모드와 배치와 같은 자원 조건에서 활성 측정과 유휴 기준을
연결한다. CPU 관측값의 수치 동일성을 자원 보장이나 matching 조건으로 쓰지 않는다.
과거 quota/affinity 실행 결과를 새 공유 실행의 근거로 자동 재사용하지 않는다. 사용자 승인으로 완료한 일회성 저장 계약 전환의 기존 프로파일 재사용은 [현행 사용자 결정](../intent/decision-log.md#완료된-저장-계약-전환의-보존-경계)에 한정한다. 원래 조건과 예측 오차의 한계를 보존한다.
배치 크기는 한 번의 실행 단위에서 함께 처리하는 요청 수다. Serving의 각 요청은
원시 표본 1개이며, 같은 워크로드의 호환되는 요청들을 내부 실행 배치로 묶는다.
프로파일의 배치별 실행 시간과 처리량은 요청별 대기와 응답 지연을 판단하는 근거다.

메모리는 배치 가능 여부를 판단하는 근거다. 실행 조건별 메모리 점유와 관측 최대값을
측정 구간과 함께 보존하며, 메모리 한도를 바꿔 성능 곡선을 탐색하지 않는다.
스케줄러는 이 근거로 필요한 메모리를 산정하고, 프로파일에 포함되지 않은 서빙
부가 사용량과 시스템 예약분도 고려해 노드의 가용 예산 안에 배치한다.
관측 최대값을 모든 입력과 실행 상태의 절대 상한으로 간주하지 않는다.

프로파일의 각 배치 `memoryBytes`는 해당 배치 크기 인스턴스의 컨테이너 수명 동안의
메모리 최댓값이며 모델 적재를 포함한다. 값은 노드 에이전트가 읽는다.
최댓값 계수기가 없는 커널에서는 같은 기록의 현재값 표본 중 최댓값이며,
이를 적재 최댓값으로 해석하지 않는다. 메모리를 관측하지 못한 배치 크기는
메모리 값 없이 서비스 시간 기록만 남는다. 다른 배치와 프로파일의 값은 섞지 않는다.
Catalog read의 배치별 `memoryBasis`는 관측 종류(`peak`, `current-sample-maximum`)와
원본 evidence store/key를 제공한다.

### 공존 오차와 서비스 검증

먼저 선택한 할당 조건에서 단독 모델의 특성을 측정하고, 실제 공존 구성에서
지연, 처리량과 전력의 차이를 확인한다. 공존 여부와 함께 실행한 구성은 해석에 필요한
조건으로 남기되, 가능한 모든 모델 조합을 ProfilingRun의 필수 측정 축으로 넣지 않는다.
관측된 차이가 제어 판단을 방해하는 경우 해당 구성의 추가 측정이나 운용 제한을 정한다.

실행 조건이 같은 워크로드들은 SLO가 달라도 동일한 실행 조건의 성능 측정을
재사용한다. 각 워크로드는 자기 인스턴스에서 처리하고, 프로파일과 배칭 정책 및 현재 timing으로 유한 수요를 직접 재생한다.
직접 후보 평가는 현재 유한 수요, 요청 상태와 전환을 같은 실행 정책으로 재생한다. 전체 격자의 용량 계산은 명시적 offline 조회로 구분하며 online 판단의 선행 gate로 두지 않는다. 예측 오차는 종단 Serving 평가와 비교한다.

## 스케줄러가 답을 필요로 하는 질문

| 질문 | 필요한 근거 |
|---|---|
| 이 구성에서 어느 정도의 요청을 맡길 수 있는가? | 실행시간 분포와 처리량과 현재 부하, 큐와 배칭 조건 |
| 워크로드의 SLO를 만족할 수 있는가? | 프로파일과 현재 요청 상태로 계산한 요청별 지연 분포 |
| 같은 부하를 더 적은 에너지로 처리할 수 있는가? | 구성별 전력과 에너지, 유휴 소비, 완료 요청 수 |
| 어떤 전력모드와 배치가 유리한가? | 해당 모델과 실행 경로에서 설정별 측정 결과 |
| 필요한 인스턴스들을 노드에 배치할 수 있는가? | 실행 조건별 메모리 사용량과 노드의 가용 자원 |
| 다른 구성으로 이동할 가치가 있는가? | 전환 시간과 에너지와 그동안의 서빙 가능 여부 |

추론을 연속 실행한 최대 처리량을 SLO를 지키며 감당할 수 있는 요청률과 동일시하지
않는다. 프로파일은 배치별 실행시간과 그 변동성을 제공하고, 스케줄러는 후보 구성의
처리 규칙과 현재 요청 상태로 유한 수요를 직접 재생해 SLO를 평가한다.
프로파일에 포함되지 않은 시간 중 인스턴스를 점유하는 부분은 디스패치 점유로
용량 계산에 더한다. 프로파일은 포화 수준의 연속 배치 쌍에서 구한 점유 시간을 배치 크기마다 담고, 단독 점유 측정도 남아 있다. 나머지 전달과 응답 처리 시간은 설정 여유로 반영하고 Serving
관측으로 그 여유를 검증한다. 이 계산에 부하별 Serving 프로파일링 캠페인을 선행 조건으로 두지 않는다.
실제 SLO와 에너지와 예측 오차는 기존 종단 평가에서 검증한다.

### 디스패치 점유 측정의 공급과 결과

고정 배치 인스턴스에 closed-loop 부하를 보내며 worker 수, 예열, 측정 길이, 최소 연속 배치 쌍 수, 요청 수명, 전달 여유와 전체 실행 상한을 설정에서 선택해 동결한다. worker 수는 1부터 64까지다. 요청 개수와 decoded bytes의 native 큐 상한, 실제 배치 서비스 시간과 요청 수명으로 공급 가능성을 검증하며 불가능하면 실행 전에 거절한다.

정해진 예열을 제외하고 실제 물리 실행의 연속 배치 쌍을 연결한다. 점유시간은 앞 배치의 실제 서비스 시간을 차감한 signed 요청당 잔차다. 표본이 부족하거나 물리 근거와 관측 구간이 불완전하면 불충분으로 남긴다.

결과는 쌍과 배치 및 요청 수, 중앙값, 사분위수, 분산 범위, 평균과 음수 비율을 제공한다. 정밀도와 포화, SLO는 각각의 평가 근거로 판정한다. 현재 burst 판정에는 별도의 유휴 5% 또는 요청당 1ms 수용 문턱을 두지 않는다. 기존 불변 결과를 재판정하거나 자동 재측정하지 않는다.

배치를 키우면 항상 효율이 좋아진다거나, 같은 타입의 노드는 항상 같은 성능을
낸다고 전제하지 않는다. 노드, 전력모드와 배치의 비교는 해당 측정 결과를 사용한다.

## 전력과 에너지

전력은 노드 전체의 벽전력을 기준으로 관측한다. edge-metrics 같은 수집 경로로
얻은 값에는 대상, 단위, 측정 시각과 측정 구간이 연결되어야 한다.

프로파일의 노드 전력은 네 값이다.

| 값 | 뜻 |
|---|---|
| 유휴 전력 | 모델을 올린 채 요청이 없고 전력이 가라앉은 상태의 벽전력(와트) |
| 깨어 있는 전력 증가 | 요청을 처리한 직후 노드가 머무는 상태와 유휴의 전력 차이(와트) |
| 유지 시간 | 마지막 실행 뒤 깨어 있는 상태가 이어지는 시간(초) |
| 입력당 에너지 | 배치 크기마다, 입력 하나가 더하는 에너지(줄) |

노드 전력은 `유휴 전력 + 깨어 있는 전력 증가 × 깨어 있는 비율 + 입력당 에너지 × 입력률`이다. 깨어 있는 비율은 노드가 실행 중이거나 마지막 실행이 끝난 뒤 유지 시간 안에 있는 시간의 비율이며, 노드 단위로 계산한다. 한 노드에 구성이 여럿이면 깨어 있는 전력 증가와 유지 시간은 함께, 깨어 있는 전력 증가가 가장 큰 한 구성의 값을 쓴다. 세션이 정하지 못한 값은 식별되지 않음으로 게시한다. 입력당 에너지가 식별되지 않은 배치 크기는 Serving에 제공하지 않는다. 식이 필요로 하는 값이 식별되지 않으면 그 노드의 에너지는 비교할 수 없음으로 다루고 수치로 바꾸지 않는다.

- 모델이 준비된 채 요청을 처리하지 않는 유휴 상태와 서빙 비참여 상태를 구분한다.
- 연산 중의 전체 노드 전력에 유휴 전력이 이미 포함되어 있으면 다시 더하지 않는다.
- 전체 POOL 전력은 같은 시점의 노드 전력 합이며, 에너지는 해당 기간의 전력을
  누적한 값이다. 활성 POOL의 소비는 별도로 집계할 수 있다.
- 요청당 전체 에너지와 유휴 소비를 뺀 증분 에너지를 구분한다. 증분 에너지를
  전체 소비로 사용하거나 유휴분을 중복 계산하지 않는다.
- 같은 노드에 파드가 여러 개 있어도 노드 전력은 한 번만 집계한다. 각 파드의
  단독 실험에서 측정한 노드 전체 전력을 더해 공존 비용을 만들지 않는다.
- 운영 전력 창의 읽기 실패는 성공 표본 사이의 gap으로 취급하며 실패 한 건만으로
  불완전 처리하지 않는다. 기록된 최대 gap와 최소 coverage와 경계 거리 정책으로 판정하고,
  노드별 창 안 읽기 실패 횟수와 실제 표본 최대 간격 및 창 합계/최대값을 보고한다.
  전력 공백의 최대 간격, 최소 coverage와 경계 거리는 해당 측정의 설정으로 선택하고 동결한다. 운영 관측, 짧은 비용 측정과 긴 평가 구간의 정책을 혼용하지 않는다. 정책을 초과한 결손은 미확인으로 남긴다.

운영자는 한 노드의 준비, 유휴, 해제, 빈 노드 전력모드 변경을 순서 있는 측정 요청 하나로
선언한다. 동작마다 기록을 남기고 기록은 그 요청을 가리킨다.

노드 편입과 모델 준비와 전력모드 변경 등은 소요 시간과 에너지를 측정하고, 전환 중
추론을 계속할 수 있는지 관측한다. 임시 자원을 포함한 POOL 전환 비용의 합성은
[구성 선택](04_configuration_selection.md)에서 다룬다.

## 측정 설정과 실패

수준 시간 한도, 표본 하한, 최소 전력 관측 시간, 전력계 지연, 신뢰 수준, 통계 계산에 필요한 값은 측정 입력으로 설정하고 결과와 함께 남긴다. 구체적인 값은 측정 목적과 연구 근거에 따라 선택한다.

용량 한계와 서빙할 수 없는 배치 크기는 정상 종료다. 그 앞 배치 크기까지가 결과다. 한 수준, 한 배치 크기, 한 값의 문제는 그 항목만 제외한다. 사용할 수 있는 포화 수준을 가진 배치 크기가 하나도 없을 때만 세션이 실패하며, 실패는 원래 오류 문장을 싣는다. 준비와 제거의 비용 기록은 세션의 부산물이므로 이 기록의 부족은 세션을 실패시키지 않는다.

계산할 수 없는 입력은 오류로 드러낸다. 없는 수치를 채워 넣지 않는다. 세션이 정하지 못한 값은 식별되지 않음으로 남긴다. 열 상태와 간섭은 필요하면 관측 자료로 보존하되, 별도의 제어 대상이나 자동 합격과 불합격 정책으로 요구하지 않는다.

## Evidence Store의 역할

Evidence Store는 측정 설정, 원시 관측, 실행 결과와 파생 결과를 보존한다.
파생 결과에는 어떤 측정과 계산 조건을 사용했는지 연결한다. 이를 위해 별도의
일반화된 신뢰도 판정 시스템을 만들 필요는 없다.
실험 구간의 관측은 사후 재생이 가능한 동안 보존하고, 조회는 보존 위치가 로컬인지
근거 저장소인지에 관계없이 투명하게 같은 구간의 관측을 제공한다.
실험이 참조하는 부하 trace, 씨앗과 시작 상태는 내용이 고정된 증거로 보존한다.
실험 정의와 실행 기록과 판정 증거를 서로 연결하며, 정의가 참조하는 증거는 삭제하지 않는다.

- 스케줄러는 워크로드와 실행 대상에 맞는 프로파일을 조회하고, 측정한 실행 구성만
  선택한다. 대상이 맞지 않거나 필요한 측정이 없으면 그 후보를 선택하지 않는다.
- 현재 선택은 모델, 기종, 실행 경로와 전력모드 셀의 최신 측정이다. 최신 실패나 부분 결과를 과거 성공으로 대체하지 않는다. 공개 성공 이력과 현재 선택을 구분한다.
- 프로파일링을 요청하는 것은 운영자의 역할이다. 완료된 측정 결과는 해당 노드를
  그 워크로드의 후보로 만든다. 자동 만료와 노후화 판정은 요구하지 않는다.

조회 결과는 구성별 특성을 제공한다. 스케줄러가
현재 부하와 상태에 대입하여 후보를 비교한다. 필요한 파생 표와 조회 형식은 그
입력이 구체화될 때 정하며, 특정 CRD나 저장 엔진을 명세의 전제로 삼지 않는다.
