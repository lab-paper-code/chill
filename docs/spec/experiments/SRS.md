# 실험 관리 SRS

상태: 요구사항 명세. 구현, 배포와 측정 수용 완료를 뜻하지 않는다.

## 1. 목적과 범위

이 문서는 evaluation 평가 실험의 선언형 정의, 독립 실행, 상태와 증거의 정본이다.
[시스템 명세](../README.md#실클러스터-검증과-평가)를 구체화하며 요구사항 ID는 [불변 실험 정의](#불변-실험-정의)부터 쓴다.
범위 밖은 시험 대상 배포와 업그레이드, 다중 자원 풀 실험, 과거 게시 재해석과 판정 규칙 자체 변경이다.
리소스의 구체적인 종류와 필드, API 경로와 실행 배치는 설계/ADR에서 정한다.

## 2. 용어와 소유

| 용어 | 의미와 소유 |
|---|---|
| 실험 정의 | 질문, 조건, 계획과 증거 참조를 담은 불변 선언형 클러스터 리소스 |
| 실행 상태 | 대기, 현재 수행 위치, 수행 결과와 증거 저장 여부를 담는 가변 기록. 정의 변경과 구분 |
| 실험 단계 | 정의에 나열된 자율 운영과 고정 구성과 제어요소 비활성 비교 단위 |
| 수행 절차 | 각 실험 단계 안의 준비와 시작 상태 복원, 부하, drain, 수집, 판정과 정리 |
| 실행 주체 | ChillServer와 별도 생명주기로 실험을 수행하고 상태를 갱신하는 주체 |
| drain | 신규 부하 발행을 끝내고 이미 발행한 요청의 결과를 정해진 상한까지 기다리는 절차 |
| 증거 저장소 | 내용이 고정된 입력과 원시, 판정과 실행 기록을 보존하는 기존 Evidence Store |

## 3. 요구사항

#### 불변 실험 정의
실험 정의는 선언형 클러스터 리소스여야 한다. 생성 경계에서 필수 입력의 구조와 의미를 한 번 검증하고, 생성 후 정의 변경은 실행 전에도 거부해야 한다. 정정은 새 정의로 해야 하며 실행 상태 갱신과 구분해야 한다.

#### 실험 정의의 필수 내용
정의는 질문, 시험 대상 구성요소의 resource 참조와 실제 관측 신원, 전력 측정 장비와 부하 생성기의 신원과 설정, 제어요소 스위치를 포함한 제어 설정, 대상 워크로드의 이름, UID와 generation, 부하 trace와 씨앗의 내용 고정 증거 참조를 담아야 한다. 실험 정의는 여러 실험이 공유하는 불변 부하 정의를 참조할 수 있고, 실행 준비에서 참조한 부하 정의와 워크로드 적용 정의(모델, 전처리와 데이터셋 신원, SLO)를 한 번 해석해 동결해야 한다. SLO는 워크로드 정의에서 가져오며 실험 정의에 복사하지 않아야 한다. 시작 시 실제 환경과 설정을 기록하고 선언한 settingsPatch를 공개 API로 적용해야 한다. 내부 시작 상태를 복원하거나 현재 이미지와 프로파일의 동일성을 추가 실행 gate로 삼지 않는다. 순서 있는 단계 목록에는 모드(자율 운영, 고정 구성과 제어요소 비활성), 시나리오와 길이를, 단계 사이 비교 관계에는 비교 대상과 이유를, 장애 주입 계획에는 주입 시각과 대상 선택 규칙과 동작을 명시해야 한다. 이름만 같은 새 워크로드나 현재 설정으로 대체하지 않고 동결한 부하 정의와 적용 정책을 재현할 수 있어야 한다.

#### 설정 선택과 동결
대기 상한 등 실행과 판정에 쓰는 설정값은 소유 설정에서 선택하고 실제값과 출처를 실행 기록에 동결해야 한다. 실행 중 설정 재조회로 선택값을 바꾸지 않아야 한다.

#### 독립 실행 경계
실행 주체는 ChillServer와 독립된 생명주기로 실행하고 ChillServer 공개 API와 Kubernetes API로만 작용해야 한다. 시험 대상의 배포 산출물을 교체하지 않아야 하며 제어 설정과 선언된 설정 적용과 장애 주입도 이 경계를 따라야 한다.

#### 시험 대상 신원 확인
공개 인터페이스에서 실제 resource UID와 준비 상태, 이미지 및 source 정보를 관측해야 한다. 실행 주체의 UID와 소유권 및 동결한 입력을 확인하며 시험 이미지 기대값 비교를 새 시작 gate로 두지 않는다. 새 다이제스트 형식, 재계산과 비교 또는 바이트 동일성 검증 관문을 추가하지 않아야 한다.

#### 자원 풀 상호 배제
같은 자원 풀에서는 생성 순서대로 한 번에 한 실험만 자동 진행하고 나머지는 점유 실험과 사유를 표시하며 대기해야 한다. 정상 반환 또는 [중단과 정리](#중단과-정리)의 운영자 확인 전에는 자원 풀을 다음 실험에 넘기지 않아야 한다. 우선순위, 재정렬과 별도 큐 관리 기능은 요구하지 않는다.

#### 단계별 수행 순서
각 단계는 실험의 일부로만 수행하며 단독 단계 실행은 허용하지 않고, 단일 단계도 실험 하나로 수행해야 한다. 공통 입력 해석과 동결(LoadScenario와 Workload 적용 정의 snapshot, 운영 설정)은 부모 prepare에서 실행당 한 번 수행해야 한다. 각 실험 단계는 동결 snapshot으로 그 단계의 신원, 입력과 장비를 확인하는 단계별 준비 → 선언된 설정 적용 → 부하 → drain → 수집 → 판정 → 정리 순서로 수행해야 하며 단계별 준비에서 공통 입력을 재해석하지 않아야 한다. 단계 안 정리는 그 단계가 만든 실행 자원 반환에 한정하고, 단계 사이에는 실제 설정과 환경의 관측 기록을 유지해야 한다. 제어요소 비활성 단계는 선언한 설정 patch로 해당 스위치를 적용해야 한다. 실행 전 제어 설정 복구와 실험 소유 자원 반환과 반환 대기는 실험 끝에 한 번만 수행해야 한다.

#### 수행 기록과 재시작
각 실험 단계와 수행 절차의 결과, 사유와 시작/종료 시각을 기록해야 한다. 재시작 시 결과가 기록된 단계 경계에서만 다음 절차를 이어가야 한다. 응답 없는 reset/prepare나 상태 불명 부하처럼 진행 중 단계의 결과가 불확실하면 중단하고 사유를 기록하며 예약을 유지해야 한다. 시작된 부하는 다시 발행하지 않고 기존 부하의 관측만 계속해야 한다.

#### 완료 상태의 분리
작업 완료와 측정 판정과 정리 완료를 별도로 기록해야 한다. 작업 완료나 부하 종료를 평가 통과로 표시하지 않아야 하며 수행 오류와 측정 불합격을 구분해야 한다.

#### 기존 판정 규칙
SLO, 에너지와 생성기 품질과 전력 완전성의 기존 판정 규칙을 사용하고 규칙 식별자와 실제 적용 조건, 결과와 사유를 기록해야 한다. 증거 누락과 계산 불능을 통과나 0으로 대체하지 않아야 한다.

#### 중단과 정리
실험 끝에 한 번 실행 전 제어 설정을 복구하고 자신이 만든 자원만 정확한 UID로 식별해 반환하며 설정에서 선택해 동결한 상한까지 기다려야 한다. 수행 오류가 나면 해당 절차에서 멈추고 후속 실험 단계와 자동 재측정과 자동 물리 복구를 하지 않아야 한다. 오류나 정리 대기 초과 시 잔류 실물의 신원, 할당, 소유와 예약과 마지막 관측을 보존하고 사유와 시각을 기록하며 강제 삭제하지 않아야 한다. 관측 실패나 실행 주체 종료를 자원 반환으로 보지 않고 미확인 원격 효과의 예약을 유지하며, 대기 초과는 정리 실패로 기록해야 한다. 정리 실패로 보존된 자원 풀은 운영자의 명시적 확인이 기록된 뒤에만 다음 실험에 넘겨야 한다. 정리 실패여도 확보한 증거로 측정 판정과 결과 게시를 수행하고 정리 실패를 별도로 표시해야 한다.

#### 장애 주입
주입 시각은 부하 시작 신호를 기준으로 하며 허용 오차는 설정에서 선택해 실행 기록에 동결해야 한다. 실행 주체는 정의의 주입 계획대로 수행하며 실제 선택 근거, 명령, 응답과 시각을 기록해야 한다. 대상 조건 불만족이나 허용 창 초과 시 임의 대체와 지연 주입 없이 취소하고 해당 실험 단계의 주입 평가를 무효로 기록해야 한다.

#### 불변 증거와 참조 보호
원시, 판정과 실행 기록을 증거 저장소에 불변 저장하고 정의, 상태와 결과를 연결해야 한다. 정의에서 참조할 실행 증거 위치는 생성 시 고정하고 실제 저장 완료 여부는 상태에 기록해야 한다. 참조 증거 보호는 실행 주체와 판정 주체에 증거 삭제 권한을 부여하지 않는 것으로 충족하며 별도 참조 삭제 거부 기능은 요구하지 않는다. 저장 실패를 증거 완료로 표시하지 않아야 한다.

#### 실행 결과와 게시
실험 요약 게시물은 이 실행 결과의 한 표현이어야 한다. 기존 과거 게시를 수정과 재게시하거나 새 정의로 소급 해석하지 않아야 하며 정정 게시는 새 ID로 해야 한다.

#### 조회와 해석 경계
화면과 게시 조회 API는 완료된 실행 결과의 게시를 읽으며 진행 중 상태는 클러스터 리소스 조회로 확인해야 한다. 완료 결과에 연결된 정책과 비교 관계는 실험 정의에서, 판정과 적용 SLO는 정의와 실행 결과의 기록에서 읽고 단계 이름이나 요청률 유사성으로 추측하지 않아야 한다. 정의 없는 과거 게시는 비교 관계를 ‘미기록’으로 표시해야 한다.

설정 소유는 [Configuration Ownership and Freezing Paths](../../adr/0031-configuration-ownership-and-freezing.md), 미확인 자원은
[Resource Ledger and Scoped Reservations](../../adr/0023-resource-ledger.md)을 따른다. 저장 계약은 캠페인 의존 중 바꾸지 않으며
[Durable Stored-Contract Compatibility](../../adr/0019-durable-stored-contract-compatibility.md)의 단일 reader를 유지한다.
기존 게시 불변성은 [관측 설계 §6.4](../../design/serving/measurement-api.md#실험-조회와-저장-계약)가 정본이다.

### 정상 완료와 판정 분리

- Given 같은 풀을 사용하는 실험 정의에 자율, 고정과 제어요소 비활성 단계와 비교 이유, 선언한 설정 patch와 실제 시작 환경 기록, 워크로드 신원, 장비와 제어 설정이 있다.
- When 부모 prepare가 공통 입력 해석과 동결(LoadScenario와 Workload 적용 정의 snapshot, 운영 설정)을 실행당 한 번 수행하고, 독립 실행 주체가 그 snapshot으로 단계별 신원, 입력과 장비를 확인하는 준비와 나머지 절차와 실험 끝 정리를 완료하여 기존 규칙으로 판정한다.
- Then 단계별 준비는 공통 입력을 다시 해석하지 않는다. 스위치는 선언한 설정 적용 절차에서 반영되고 단계 안 정리는 그 단계의 실행 자원만 반환하며 단계 사이 실제 환경과 설정의 기록을 유지한다. 실험 끝에 한 번 원래 설정을 복구하고 자신의 정확한 UID 자원을 반환하고 기다리며 실제 설정값, 출처와 절차별 시각과 증거를 기록한다.
- Then SLO 불합격이어도 작업 완료와 측정 불합격과 정리 완료가 분리된다. 완료 게시 화면에서는 정의에 명시된 정책과 비교 관계와 규칙 식별자를 읽고 진행 중 상태는 클러스터 리소스로 확인한다. 정의 없는 과거 게시의 비교 관계는 ‘미기록’이다.

### 생성 후 정의 변경

- Given 생성된 실험 정의가 있고 아직 부하를 시작하지 않았다.
- When 실행 전 또는 실행 중에 질문, 입력과 단계 중 하나를 수정한다.
- Then 변경을 거부하고 기존 정의를 보존한다. 정정은 새 정의로 접수하며 상태 갱신은 정의 수정으로 취급하지 않는다.

### 시험 대상 관측과 실행 주체 신원

- Given 대상 resource 참조와 동결된 부하 정의가 있다.
- When 준비 절차가 resource UID, 준비 상태와 실제 이미지 정보를 관측한다.
- Then 관측 사실을 보존한다. 기대 이미지나 source SHA 비교를 시작 gate로 추가하지 않는다. 동결 입력과 실제 실행 Job/Pod의 UID 및 소유권은 확인한다.

### 동시 실험 대기

- Given 같은 자원 풀에 생성 순서가 A → B → C인 실험이 있고 A가 수행 중이다.
- When B와 C가 대기 중이거나 A의 관측이 끊겨 반환 여부가 미확인이다.
- Then B와 C는 점유 실험 A와 사유를 표시하며 부하, 복원과 주입을 시작하지 않는다. A가 정상 반환되거나 정리 실패 후 운영자의 명시적 확인이 기록되면 B, 그 뒤 C 순서로 자동 진행하며 우선순위나 재정렬은 적용하지 않는다.

### 부하 중 실행 주체 재시작

- Given 부하 시작과 생성 자원 UID가 기록되어 있고 그 부하는 아직 끝나지 않았다.
- When 실행 주체가 재시작한다.
- Then 시작된 부하는 다시 발행하지 않고 기존 부하의 관측만 계속한다. 결과가 기록된 단계 경계에서만 다음 절차를 이어가며, 상태 불명 부하나 응답 없는 reset/prepare 등 불확실한 진행 중 단계는 중단과 사유 기록과 예약 유지로 처리한다.

### 정리 대기 초과

- Given 실험 끝의 정리 대상 UID와 예약이 남아 있고 원래 제어 설정과 대기 상한이 동결되어 있다.
- When 반환 완료 관측 없이 그 상한을 넘거나 관측에 실패한다.
- Then 정리 실패, 사유, 시각과 잔류 실물과 마지막 관측을 보존하고 확보한 증거로 측정 판정과 게시를 수행한다. 강제 삭제나 반환 완료 처리를 하지 않으며 운영자의 명시적 확인이 기록된 뒤에만 자원 풀을 다음 실험에 넘긴다.

### 수행 절차 오류

- Given 아래 사례의 수행 절차가 진행 중이며 정의와 입력 참조와 이미 확보한 관측과 증거가 있다.
- When 입력 부재와 증거 읽기 실패와 수집기 오류와 증거 저장 용량 부족 중 하나를 확인한다.
- Then 해당 절차의 실패, 사유, 시각과 원 참조를 기록하고 멈춘다. 확보한 증거와 마지막 관측과 예약을 보존하며 자동 재측정과 물리 복구와 다른 실행 증거 대체를 하지 않는다.

| 사례 | 발생 위치와 부하 시작 여부 | 추가 확인 결과 |
|---|---|---|
| 필수 입력 부재 | 준비에서 동결된 부하 정의나 입력 증거 부재, 부하 시작 전 | 누락 참조와 준비 실패 기록, 다른 입력 대체와 부하 시작 금지 |
| 증거 읽기 실패 | 부하 후 판정 입력을 읽거나 해석할 수 없음 | 원 참조와 읽기 오류와 판정 미완료 기록, 0와 통과 대체 금지 |
| 수집기 오류 | 준비 중 수집기 기동 오류, 부하 시작 전 | 종료 코드와 원 오류 출력의 증거 참조와 준비 실패 기록, 시험 대상 성능 불합격으로 바꾸지 않음 |
| 증거 저장 용량 부족 | 부하 후 원시와 판정 일부 보존 뒤 다음 기록 저장 실패 | 저장 실패와 미완료를 상태에 기록하고 기존 원시와 판정 보존, 완료 게시와 기존 증거 삭제 금지 |

### 장애 주입 조건 불만족과 허용 창 초과

- Given 부하 시작 신호 기준 주입 시각과 허용 오차가 동결되어 있고, 그 시각에 선택 규칙을 만족하는 서빙 Pod가 없거나 허용 창을 이미 놓쳤다.
- When 실행 주체가 대상 조건과 실제 시각을 확인한다.
- Then 선택 근거, 시각과 주입 취소와 평가 무효를 기록하고 명령을 보내지 않는다. 다른 Pod나 다른 시각으로 임의 대체하거나 허용 창 뒤에 늦게 주입하지 않는다.

### 증거 삭제 권한과 기존 게시

- Given 실험 정의가 입력과 실행 증거를 참조하고 기존 요약이 게시되어 있다.
- When 실행 주체와 판정 주체의 증거 저장 권한과 과거 게시 정정 방법을 확인한다.
- Then 두 주체에 증거 삭제 권한을 부여하지 않고 기존 게시를 보존한다. 정정은 새 정의와 새 게시 ID로 남기며 별도 참조 삭제 거부 기능을 요구하지 않는다.
