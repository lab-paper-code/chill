# 실험 관리 SRS

상태: 요구사항 명세. 구현·배포·측정 수용 완료를 뜻하지 않는다.

## 1. 목적과 범위

이 문서는 E5 평가 실험의 선언형 정의, 독립 실행, 상태와 증거의 정본이다.
[시스템 명세](../README.md#실클러스터-검증과-평가)를 구체화하며 요구사항 ID는 `EXP-01`부터 쓴다.
범위 밖은 시험 대상 배포·업그레이드, 다중 자원 풀 실험, 과거 게시 재해석과 판정 규칙 자체 변경이다.
리소스의 구체적인 종류·필드, API 경로와 실행 배치는 설계/ADR에서 정한다.

## 2. 용어와 소유

| 용어 | 의미와 소유 |
|---|---|
| 실험 정의 | 질문·조건·계획·증거 참조를 담은 불변 선언형 클러스터 리소스 |
| 실행 상태 | 대기, 현재 수행 위치, 수행 결과와 증거 저장 여부를 담는 가변 기록. 정의 변경과 구분 |
| 실험 단계 | 정의에 나열된 자율 운영·고정 구성·제어요소 비활성 비교 단위 |
| 수행 절차 | 각 실험 단계 안의 준비·시작 상태 복원·부하·drain·수집·판정·정리 |
| 실행 주체 | ChillServer와 별도 생명주기로 실험을 수행하고 상태를 갱신하는 주체 |
| drain | 신규 부하 발행을 끝내고 이미 발행한 요청의 결과를 정해진 상한까지 기다리는 절차 |
| 증거 저장소 | 내용이 고정된 입력과 원시·판정·실행 기록을 보존하는 기존 Evidence Store |

## 4. 수용 시나리오

아래 표와 Given/When/Then은 수용 기준이며 이번 문서 작성에서 실행한 결과가 아니다.
실패 사례는 실제 운영 STOP 유형(정리 대기·입력 부재·증거 읽기·수집기·용량 부족)을 반영한다.

| 시나리오 | 확인 결과 | 요구사항 |
|---|---|---|
| 정상 완료와 판정 분리 | 계획대로 완료하고 세 완료 축·증거·조회·게시 연결, 불합격도 작업 완료와 구분 | EXP-02~04, EXP-07, EXP-09~11, EXP-13~15 |
| 생성 후 정의 변경 | 실행 전·중 변경 거부, 새 정의로 정정 | EXP-01 |
| 시험 대상 신원 불일치 | 부하 미시작과 기대·관측 신원 기록, 배포 교체 없음 | EXP-04~05 |
| 동시 실험 대기 | 점유 실험·사유를 표시하고 생성 순서대로 하나씩 진행, 미확인 반환 중에는 대기 | EXP-06, EXP-11 |
| 부하 중 실행 주체 재시작 | 기존 부하 관측만 계속, 불확실 단계 중단·예약 유지 | EXP-08, EXP-11 |
| 정리 대기 초과 | 정리 실패와 잔류 UID·예약·관측 보존, 강제 삭제 없음 | EXP-03, EXP-09, EXP-11 |
| 수행 절차 오류(아래 4사례) | 해당 절차에서 사유와 증거를 보존하고 중단, 사례별 부하·판정·저장 상태 구분 | EXP-02, EXP-07~11, EXP-13 |
| 장애 주입 조건 불만족 | 주입 취소·평가 무효·선택 근거 기록, 임의 대상 대체 없음 | EXP-12 |
| 참조 증거 삭제 요청 | 삭제 거부와 참조 이유 제공, 과거 게시 유지 | EXP-13~14 |

### 정상 완료와 판정 분리

- Given 같은 풀을 사용하는 실험 정의에 자율·고정·제어요소 비활성 단계와 비교 이유, 입력 증거·워크로드 신원·장비·제어 설정이 있다.
- When 독립 실행 주체가 공개 API로 각 단계의 일곱 절차를 완료하고 기존 규칙으로 판정한다.
- Then 스위치는 복원 절차에서 적용되고 원래 설정은 정리에서 복구되며 자신의 정확한 UID 자원만 반환된다. 실제 설정값·출처·절차별 시각과 증거가 기록된다.
- Then SLO 불합격이어도 작업 완료·측정 불합격·정리 완료가 분리된다. 정의·상태·결과와 그 요약을 조회하면 명시된 정책·비교 관계·규칙 식별자가 일치한다.

### 생성 후 정의 변경

- Given 생성된 실험 정의가 있고 아직 부하를 시작하지 않았다.
- When 실행 전 또는 실행 중에 질문·입력·단계 중 하나를 수정한다.
- Then 변경을 거부하고 기존 정의를 보존한다. 정정은 새 정의로 접수하며 상태 갱신은 정의 수정으로 취급하지 않는다.

### 시험 대상 신원 불일치

- Given 정의의 시험 대상 신원과 공개 API에서 관측한 신원이 다르다.
- When 준비 절차가 그 불일치를 확인한다.
- Then 기대·관측 신원과 준비 실패를 기록하고 부하를 시작하지 않는다. 실행 주체가 배포를 교체하거나 별도 다이제스트 검증 관문을 수행하지 않는다.

### 동시 실험 대기

- Given 같은 자원 풀에 생성 순서가 A → B → C인 실험이 있고 A가 수행 중이다.
- When B와 C가 대기 중이거나 A의 관측이 끊겨 반환 여부가 미확인이다.
- Then B와 C는 점유 실험 A와 사유를 표시하며 부하·복원·주입을 시작하지 않는다. A의 반환이 확인되면 B, 그 뒤 C 순서로 자동 진행하며 우선순위나 재정렬은 적용하지 않는다.

### 부하 중 실행 주체 재시작

- Given 부하 시작과 생성 자원 UID가 기록되어 있고 그 부하는 아직 끝나지 않았다.
- When 실행 주체가 재시작한다.
- Then 시작된 부하는 다시 발행하지 않고 기존 부하의 관측만 계속한다. 결과가 기록된 단계 경계에서만 다음 절차를 이어가며, 상태 불명 부하나 응답 없는 reset/prepare 등 불확실한 진행 중 단계는 중단·사유 기록·예약 유지로 처리한다.

### 정리 대기 초과

- Given 정리 대상의 정확한 UID와 예약이 남아 있고 원래 제어 설정과 대기 상한이 동결되어 있다.
- When 반환 완료 관측 없이 그 상한을 넘거나 관측에 실패한다.
- Then 정리 실패·사유·시각·잔류 실물과 마지막 관측을 보존한다. 기존 측정 판정은 유지하고 강제 삭제·반환 완료 처리·다음 실험 시작을 하지 않는다.

### 수행 절차 오류

- Given 아래 사례의 수행 절차가 진행 중이며 정의·입력 참조와 이미 확보한 관측·증거가 있다.
- When 입력 부재·증거 읽기 실패·수집기 오류·증거 저장 용량 부족 중 하나를 확인한다.
- Then 해당 절차의 실패·사유·시각·원 참조를 기록하고 멈춘다. 확보한 증거와 마지막 관측·예약을 보존하며 자동 재측정·물리 복구·다른 실행 증거 대체를 하지 않는다.

| 사례 | 발생 위치·부하 시작 여부 | 추가 확인 결과 |
|---|---|---|
| 필수 입력 부재 | 준비에서 시작 상태 증거 부재, 부하 시작 전 | 누락 참조와 준비 실패 기록, 현재 상태 대체·부하 시작 금지 |
| 증거 읽기 실패 | 부하 후 판정 입력을 읽거나 해석할 수 없음 | 원 참조·읽기 오류와 판정 미완료 기록, 0·통과 대체 금지 |
| 수집기 오류 | 준비 중 수집기 기동 오류, 부하 시작 전 | 종료 코드·원 오류 출력의 증거 참조와 준비 실패 기록, 시험 대상 성능 불합격으로 바꾸지 않음 |
| 증거 저장 용량 부족 | 부하 후 원시·판정 일부 보존 뒤 다음 기록 저장 실패 | 저장 실패·미완료를 상태에 기록하고 기존 원시·판정 보존, 완료 게시·기존 증거 삭제 금지 |

### 장애 주입 조건 불만족

- Given 정의된 주입 시각에 대상 선택 규칙을 만족하는 서빙 Pod가 없다.
- When 실행 주체가 공개 API의 상태·신원으로 선택 조건을 확인한다.
- Then 선택 근거와 주입 취소·평가 무효를 기록하고 명령을 보내지 않는다. 비슷한 이름의 다른 Pod나 다른 시각으로 임의 대체하지 않는다.

### 참조 증거 삭제 요청

- Given 실험 정의가 입력·실행 증거를 참조하고 기존 요약이 게시되어 있다.
- When 그 증거 삭제나 과거 요약 덮어쓰기를 요청한다.
- Then 참조 증거 삭제를 거부하고 참조 이유를 제공하며 기존 게시를 보존한다. 정정은 새 정의·새 게시 ID로 남긴다.
