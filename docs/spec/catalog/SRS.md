# 데이터셋과 전처리 관리 SRS

## 1. 목적과 범위

이 문서는 CHILL 워크로드가 참조하는 전처리와 데이터셋의 등록, 조회, 수정, 삭제와
참조 관계를 정의한다. [시스템 명세](../README.md)의 워크로드 정의에서 전처리 참조와
데이터셋 참조가 가리키는 대상을 구체화한다.

요구사항 ID의 `DP`는 데이터셋과 전처리를 뜻한다. 각 요구사항은 구현과 검증의 기준이다.
이 문서의 정보 이름은 외부에서 관찰할 의미를 나타내며, 리소스와 API 표현은 구현 설계에서 정한다.

| 관련 영역 | 책임과 원본 |
|---|---|
| 모델 등록 | 모델 산출물과 실행 경로는 [모델 경계 ADR](../../adr/0012-model-artifact-compatibility-boundary.md)을 따름 |
| 워크로드 참조 | 참조 검증, 원시 표본 접수 검증, 모델 변경 절차와 요청 기록은 [워크로드 관리 SRS](../workloads/SRS.md)를 따름 |
| 프로파일 | 데이터셋 표본을 사용한 측정과 측정 조건은 [프로파일링과 Evidence](../00_measurement.md)를 따름 |
| 요청 실행 | 실행 배치의 전처리, 추론, 후처리 순서는 [라우팅과 배칭](../03_routing.md)을 따름 |

## 2. 사용자와 관리 정보

### 2.1 역할

| 역할 | 동작 |
|---|---|
| 운영자 | 전처리와 데이터셋을 등록, 수정, 삭제하고 워크로드에서 참조 |
| CHILL | 선언 검증, 참조 보호, 실행 준비 시 전처리 코드 제공, 변경 적용 |

### 2.2 정의 정보

| 정보 | 소유와 의미 |
|---|---|
| 전처리 식별자 | 워크로드가 참조할 전처리 이름. 전처리 식별 범위에서 유일 |
| 원시 입력 계약 | 표본 1개를 구성하는 필드별 이름, 자료형, 크기 상한과 내용 형식. 자료형은 원시 바이트, 내용 형식은 이미지 형식이나 UTF-8 텍스트 |
| 원시 출력 계약 | 요청자가 응답으로 받는 필드별 이름, 자료형과 의미 |
| 전처리 산출물 | 대상 모델과 모델 산출물, 내용이 고정된 코드의 위치와 장비 아키텍처 |
| 데이터셋 식별자 | 워크로드가 참조할 데이터셋 이름. 데이터셋 식별 범위에서 유일 |
| 데이터셋 표본 | 내용이 고정된 위치에 보관한 원시 표본 모음과 그 레코드 필드 선언 |
| 표본 부분집합 | 프로파일링에 사용할 프로파일링 부분집합과 평가 부하에 사용할 평가 부하 부분집합 |

## 3. 요구사항

### 3.1 전처리

- `DP-01` 전처리는 식별자, 원시 입력 계약, 원시 출력 계약과 하나 이상의 전처리 산출물을 필수 정보로 가져야 한다. 원시 입력 계약은 표본 1개를 구성하는 모든 필드를 선언해야 한다.
- `DP-02` 전처리 산출물은 대상 모델과 그 모델의 산출물 하나를 지정해야 한다. 한 전처리에서 대상 모델 산출물마다 전처리 산출물은 정확히 하나여야 한다.
- `DP-03` 전처리 산출물의 코드는 내용이 고정된 위치와 장비 아키텍처로 식별해야 한다. CHILL은 실행 준비 시 이 코드를 대상 모델 산출물과 함께 실행 위치에 제공해야 한다. 코드가 사용하는 라이브러리는 대상 모델 산출물을 실행하는 runtime 환경이 제공해야 하며, 코드 적재 실패는 해당 인스턴스의 실행 준비 오류와 원인으로 드러내야 한다.
- `DP-04` 전처리 코드는 한 실행 배치의 원시 표본들을 모델 입력으로 바꾸고, 추론 결과를 요청별로 원시 출력 계약의 응답으로 바꿔야 한다.
- `DP-05` 전처리 코드는 배치의 요청마다 성공 결과와 [단위 수](../00_measurement.md#측정의-단위) 또는 실패 사유를 보고해야 한다. 보고 수가 배치의 요청 수와 다르거나 성공 요청의 단위 수가 1보다 작으면 CHILL은 해당 배치를 오류로 처리해야 한다.

### 3.2 데이터셋

- `DP-06` 데이터셋은 식별자, 내용이 고정된 표본 위치, 레코드 필드 선언, 프로파일링 부분집합과 평가 부하 부분집합을 필수 정보로 가져야 한다. 두 부분집합은 서로 다른 표본으로 구성해야 한다.
- `DP-07` 데이터셋과 전처리의 호환성은 데이터셋의 레코드 필드 선언과 전처리의 원시 입력 계약을 비교해 판단해야 한다. 원시 입력 계약의 모든 필드가 같은 이름과 자료형으로 레코드 필드에 선언되고, 각 레코드 필드의 크기 상한과 내용 형식이 계약 범위 안에 있으면 호환이다. 판단에는 두 선언만 사용해야 한다.

### 3.3 등록, 조회, 수정, 삭제

- `DP-08` 운영자는 전처리와 데이터셋을 등록, 목록 조회, 상세 조회, 수정, 삭제할 수 있어야 한다. 관리 변경 권한은 [WM-01](../workloads/SRS.md#21-역할)을 따라야 한다. 미등록 식별자의 조회는 조회 오류로 제공해야 한다.
- `DP-09` 등록과 수정 시 식별자 중복, `DP-01`과 `DP-02`의 조건, `DP-06`의 필수 정보, 전처리 산출물이 지정한 모델 산출물의 존재와 삭제 진행 여부를 검증해야 한다. 검증 오류와 거부된 변경의 처리는 [WM-06](../workloads/SRS.md#31-등록-검증)을 따라야 한다.
- `DP-10` 워크로드가 참조하는 전처리를 수정하면 영향을 받는 워크로드에 [모델 변경 절차](../workloads/SRS.md#43-모델-수정)를 적용해야 한다. 데이터셋 수정은 이후 요청하는 측정부터 적용해야 한다. 이 수정은 해당 워크로드들이 함께 참조하는 데이터셋과 전처리가 `DP-07`의 호환성을 유지할 때 수락해야 한다.

### 3.4 참조 보호

- `DP-11` 워크로드가 참조하는 전처리와 데이터셋의 삭제는 [WM-23](../workloads/SRS.md#52-모델-참조와-동적-서빙-관계)의 모델 참조와 같은 방식으로 거부해야 한다.
- `DP-12` 전처리 산출물이 대상으로 지정한 모델 산출물을 제거하는 모델 수정과 해당 모델의 삭제는 참조하는 전처리를 이유로 제공하며 거부해야 한다.

## 4. 검증 시나리오

이 표는 요구사항 검증에 사용할 동작과 확인 결과를 정한다.

| 시나리오 | 확인 결과 | 요구사항 |
|---|---|---|
| 전처리와 데이터셋 관리 | 등록, 목록과 상세 조회, 수정, 삭제를 수행하고 권한 밖 관리 변경과 미등록 식별자 조회에 오류 제공 | DP-01, DP-06, DP-08 |
| 잘못된 등록과 수정 | 미등록 대상 모델 산출물, 같은 대상의 전처리 산출물 중복, 필수 정보 누락, 식별자 중복을 거부하고 기존 정의 유지 | DP-02, DP-06, DP-09 |
| 데이터셋과 전처리 호환성 | 두 선언의 비교로 호환 여부와 불일치 필드를 제공하고, 함께 참조된 조합의 호환성을 바꾸는 수정 거부 | DP-07, DP-10 |
| 전처리 코드 제공 | 실행 준비 시 대상 모델 산출물과 함께 코드를 제공하고, 적재 실패를 실행 준비 오류와 원인으로 조회 | DP-03 |
| 배치 전처리와 후처리 | 배치의 원시 표본을 모델 입력으로 바꾸고 요청별 응답 반환 | DP-04 |
| 배치 안 표본 하나의 실패와 보고 오류 | 실패한 표본은 실패 사유를 보고하고 나머지 요청은 결과와 단위 수를 받아 완료하며, 보고 수가 요청 수와 다르거나 성공 요청의 단위 수가 1보다 작으면 배치 오류로 처리 | DP-05 |
| 참조 중인 전처리 수정 | 영향을 받는 워크로드에 모델 변경 절차를 적용하고 기존 요청 보존 | DP-10 |
| 참조 중인 대상 제거 | 워크로드가 참조하는 전처리와 데이터셋의 삭제, 전처리 산출물이 지정한 모델 산출물의 제거를 참조 이유와 함께 거부 | DP-11, DP-12 |

## 5. 구현 설계로 연결할 사항

구체적인 리소스와 API, 코드 전달 방식은
[이기종 워크로드 구현 설계](../../design/serving/heterogeneous-workloads.md)에 정리한다.

| 영역 | 구체화할 구현 |
|---|---|
| 리소스 | 전처리와 데이터셋의 리소스 표현, 객체 범위와 필드, 내용이 고정된 위치의 표현 |
| API | 관리 경로, 변경 전제조건과 오류 응답 |
| 코드 실행 | 코드 전달과 적재 위치, runtime 환경의 라이브러리 제공, 배치 입력과 응답 및 단위 수의 전달 형식 |
| 데이터셋 | 레코드와 부분집합의 표현, 프로파일링 표본 추출과 평가 부하 재생에서의 사용 |
