# 자율 워크로드 풀 시연 기록
2026-10-26 07:34Z 기준. MobileNetV2 이미지 분류(MNV), 공정 이상 탐지(PLC), SmolVLM2 영상 질의응답(Smol)을 함께 운영했다. 시연은 연구 평가 E5와 다르며 동일 조건 반복 실험이 아니다.
## 1–3회차 비교
성공률은 HTTP 성공/예정 요청 전체, p95는 성공 응답 클라이언트 왕복값이다. 셀 순서는 MNV / PLC / Smol이다. Smol의 목표는 p99이므로 p95만으로 목표 준수를 판정하지 않는다.
| 회차 | A 성공률 % | B 성공률 % | C 성공률 % | B p95 ms | 핵심 해석 |
|---|---|---|---|---|---|
| [1회차](demo1-20261025.md) | 99.85 / 100 / 30 | 63.81 / 99.77 / 100 | 100 / 99.70 / 100 | 1972 / 13.08 / 12860 | 무부하 최저 비용 첫 구성, 준비된 용량도 긴 전력 전환을 기다림 |
| 2회차 | 100 / 99.85 / 100 | 0.67 / 100 / 100 | 100 / 100 / 100 | 2001 / 15.15 / 4007 | 정상 정책 응답 대기를 실물 부재로 읽은 사고; 별도 보고서 없음 |
| [3회차](demo3-20261026.md) | 100 / 100 / 100 | 85.36 / 100 / 100 | 100 / 100 / 100 | 870 / 67.09 / 4132 | 실물·예약 장부로 확장 회복; 첫 60초 5,286개 손실 및 게이트웨이 퇴행 |
1회차 A Smol은 0.2 req/s, 2·3회차는 0.3 req/s이고 공백과 시작 구성이 다르다. 전체 풀 에너지는 작업별 귀속값이 아니며 행별 합산·회차별 단순 절감률 계산을 하지 않는다. 원 보고서의 다음 할 일은 당시 상태이며 아래 후속 처리로 대체된다.
## 2회차 사고와 결정
정책 응답 대기 → 관측 오류 → 스냅샷에서 인스턴스 누락 → 같은 자리·CPU 중복 준비 → CPU 독점 위반의 전역 검사로 모든 판단 정지. B 부하 360초 안 실제 배치 변경은 0회였다. 공백 포함 재집계 10회와 혼동하지 않는다.
개별 예외 패치 대신 약 25개 발견을 다섯 본질로 조사한 뒤, 사용자는 시연 3회차 전 기존 프로세스 안에 Pod 실물 장부·작업별 영향 범위 예약·범위별 고정을 채택했다. 새 서비스·저장소·사용자 정의 자원(CRD)은 만들지 않는다. [사고 보고서](../../postmortems/0002-demo2-duplicate-preparation.md), [자원 장부 결정](../../adr/0023-resource-ledger.md), [구조 검토](../structure-review-20261026.md).
