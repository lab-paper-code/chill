# CHILL 시스템 명세 보고서

상세 계약의 정본은 [시스템 명세](../spec/README.md)와 각 SRS다. 이 보고서는 요구의 결론이며 구현 완료·실측 성능을 주장하지 않는다.

- 목표: 이기종 추론 자원에서 지연 SLO를 우선 충족하는 선택 중 전환+Serving의 전체 POOL 총에너지를 최소화한다. 현 상태 유지도 후보다.
- 책임: 운영자는 모델·워크로드·측정/적용 대상을 지정하고, Evidence는 실측 조건·원시·파생 결과를 보존한다. 스케줄러는 구성/분배/배칭/전환을 선택하고 실행 계층은 실제 완료·실패를 보고한다. Triton 실행 메커니즘을 재사용한다.
- 요청은 독립 입력 1개이며 최초 CHILL 수신부터 응답 완료까지 지연을 잰다. 동일 모델의 서로 다른 SLO 워크로드를 허용하고 이미 수락한 요청의 의미·소유를 보존한다.
- 노드는 동시에 하나의 POOL에 속한다. 파드당 모델 인스턴스 하나, `instance_group.count=1`, 인스턴스별 동시 배치 하나. CPU 집합·물리 GPU를 전용 할당하고 CPU 스레드는 할당량에 연동한다. 메모리·공존·호스트 전력모드는 배치 제약/비용에 반영한다.
- 프로파일링과 Serving은 같은 Triton/backend 경로를 쓴다. 실행·입력·자원 조건 일치, 요청/실제 적용 조건, 활성/유휴 연결, 반복 trial과 최신 성공 측정을 구분한다. 단독 후 공존 오차를 관측하며 실패·필수 관측 누락은 오류다.
- 후보는 같은 시간축·부하·전체 POOL로 비교한다. 전환 에너지+이후 Serving 에너지에 비참여 노드 소비도 포함하며 유휴/공유 로드 비용을 중복 계산하지 않는다. 벽전력을 적분하고 총/증분 에너지를 구분한다.
- SLO는 요청별 예상 완료/종단 분포로 판단한다. 모든 후보가 초과해도 가용 자원으로 대응하며 전체 용량 한계와 준비 지연을 구분한다.
- 준비된 인스턴스로 즉시 전달하며 분배 비율은 비음수·대상 존재 시 합 1이다. 호환되는 같은 워크로드 요청만 배칭한다. Triton 내부 batcher가 경과 시간·실행/반환 비용·큐·현재 실행을 고려해 대기 종료를 판단한다. 큐 timeout은 큐 대기 범위다.
- 전환은 실제 추론 준비·전력모드·자원 적용을 확인한다. 신규 유입 중지 후 남은 요청을 마무리한다. 실패 후 의존 실행을 멈추고 부분 완료된 실제 상태에서 재판단한다. 사라진 노드/백엔드는 격리하며 복구도 실제 상태로 확인한다.
- 관측은 요청 수명·분배/배치·제어·벽전력을 같은 시간축으로 연결한다. `inputs/s=requests/s`, 큐 길이는 요청 수다. 표본 0은 값 없는 통계로 남기고 오류·거절·timeout·취소·미완료·SLO 위반을 구분한다.
- 평가는 일정/점진/버스트/재급증/용량 초과/실패 시나리오의 지연·처리 결과·전체 POOL 총에너지다. 정적 구성·제어요소 비활성화와 비교하고 조건·원시·예측/실측 대응을 보존한다. 분석자가 성패를 판정한다.

## 후속 설계 (보고서 작성 당시)

- 구성 선택: 비교 기간·부하 처리·후보 탐색/비교 알고리즘.
- 제어: 관찰/제어 주기·전환 재판단·취소/완료 규칙·플랫폼 자원 변경.
- Triton: 시간 예산 전달·에너지 배칭·큐 선택·정책 적용/갱신 지점과 실제 계약 검증.
- 워크로드/자원: API/리소스 표현·관리 SRS 적용·워크로드 간 할당.
- 라우팅/측정: 분배 표현/선택/갱신·측정 절차/조회. 구체 알고리즘·공식·API·CRD·저장 엔진은 해당 설계가 결정한다.
