# 07. 제안을 확정·기각할 측정

우선순위 순. testbed 변경은 AGENTS.md에 따라 사용자 요청이 있을 때만 수행한다.

| # | 측정 | 대상 | 통과 기준(예) | 기각 시 |
|---|---|---|---|---|
| 1 | **M4 오프라인 A/B**: 기존 결정 기록 N건(입력 전체 내장)에 분석형 평가기를 돌려, 재생이 고른 target과의 일치율, 에너지·SLO 판정 차이 | B1 | target 일치 또는 에너지 차 ≤5%, SLO 판정이 재생보다 낙관적인 경우 없음 | 상한 보수성(ρ, 분위수) 조정. 반복 실패 시 재생 유지 + M0만 적용 |
| 2 | **E1/E5 실측**: 부하 단계별 창마다 예측 p와 관측 p 비교, 과대 프로비저닝 에너지 | B1 | ≥95% 창에서 예측 ≥ 실측, 재생 선택 대비 에너지 손해 ≤5% | 같음 |
| 3 | **edge CPU 노드 꼬리 지연**: RPi5, RK3588(및 LattePanda)에서 열 상태별 `l_q(b)` 안정성 | B1 최대 위험 | 열 상태 간 `l_q` 변동이 SLO 여유 안 | 해당 노드 클래스만 재생 검증 강화 또는 상한 보수화 |
| 4 | **M0 전후**: 결정 기록 크기, ChillServer RSS, PVC 증가율, Tick p99([M0 설계 5장](../serving/decision-record-diet.md#5-e1에서-확인할-값)) | M0 | 기록 ≤100KB, RSS가 limit 아래이고 OOM 없음, PVC 시간당 증가로 M1 전까지의 `observationStorage` 크기를 정함, Tick p99 기록 | 다이어트 항목 추가 |
| 5 | **B2 경쟁 test**: envtest에서 측정 요청과 prepare를 같은 노드에 1000회 동시, agent kill, 측정 객체 삭제 후 자동 반환 | B2 | 겹침 0, 자동 반환 | 설계 재검토 |
| 6 | **B3 기준선 비교**: 버스트·급감 시나리오의 진동 횟수와 에너지 | B3 vs B1 | (B1 기여 입증용) | - |

최종 검증의 절차, 증거, 기준 출처와 사용자 결정은 [08](08-final-verification.md)이다.
