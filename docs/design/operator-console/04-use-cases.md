# 운영 Use Case

T1/T2/T3, D1/D2의 계산·실행 규칙은 `docs/spec/`을 따른다. 요청 결과와 지연의 관측은
[SLO 관측과 집계](../../spec/README.md#slo-관측과-집계)를 따른다. 이 문서가 추가로
정의하는 것은 상태 판정, 승인, 유지보수, 노드 재편입과 감사에 필요한 운영 계약이다.

## UC-01. 전체 운영 상태를 판정한다

- **운영자 목적:** 교대 시작이나 이상 알림 시 시스템이 정상인지 빠르게 판단한다.
- **시스템 반응:** 워크로드별 SLO 목표, 요청 수·실제 결과와 지연 분포·백분위,
  부하·큐·전력, 관측 신선도, 운영 모드와 안전 상태, 현재·최적·목표 구성 및 진행 중인
  전환을 관측 구간과 함께 요약한다.
- **허용된 개입:** 세부 판단을 조회하거나 문제 영역의 안전한 대응 흐름으로 진입한다.
- **성공 조건:** 운영자가 정상, 관찰 필요, 즉시 개입 필요를 구분하고 그 근거를 찾는다.

## UC-02. 판단을 설명하고 과거 결정을 재구성한다

- **운영자 목적:** 현재 구성을 유지하거나 바꾼 이유와 특정 SLO·에너지 결과의 원인을
  확인한다.
- **시스템 반응:** 당시 입력과 신선도, 프로파일·정책·알고리즘 버전, 후보 구성과 제외
  제약, 방아쇠 계산, 예상 영향과 실제 결과를 decision 단위로 연결한다.
- **허용된 개입:** 현재 판단을 검산하고 구조화된 자료를 내보낼 수 있지만 과거 사실은
  수정할 수 없다.
- **성공 조건:** controller 로그에 의존하지 않고 유지·전환·거부의 근거와 결과를
  재구성한다.

## UC-03. 자동 전환을 감독한다

- **운영자 목적:** 급증 대응, 선제 증설과 경제적 전환이 정책과 안전 규칙 안에서
  진행되는지 확인한다.
- **시스템 반응:** T1/T2/T3의 발동 이유, 목표 구성, 실행 방식과 단계, 예상·실제
  시간·비용·SLO 영향, backlog 소진을 제공한다. 전환은 한 건씩 실행하며 상향 전환은
  완수하고, 하향 전환은 안전할 때만 중단한다.
- **허용된 개입:** Supervised 모드에서 경제적 전환을 승인하거나 만료되는 보류를
  설정하고, 허용된 하향 전환을 중단한다. 상향 전환 중단은 break-glass로 분리한다.
- **성공 조건:** 탐지부터 완료 또는 안전한 중단까지의 과정과 영향을 재구성한다.

## UC-04. 관측·열·노드 이상에 대응한다

- **운영자 목적:** 제어 입력이나 가용 자원이 정상 조건을 벗어났을 때 무엇이 보호되고
  무엇이 제한되는지 판단한다.
- **시스템 반응:** 관측이 오래되면 D1에 따라 T2·T3을 동결하고 T1을 유지한다. 열
  스로틀링 노드는 D2 용량으로 평가한다. 실패한 노드는 라우팅과 용량 계산에서 제외하고
  남은 자원으로 재편성하며 요청 결과와 지연을 관측한다.
- **허용된 개입:** 관측 경로를 복구하고, 안전 구성을 요청하거나 노드를 유지보수
  제외한다. 복귀 노드는 건강과 프로파일 유효성을 확인한 뒤 재편입한다.
- **성공 조건:** 잘못된 입력이나 손실된 용량을 정상으로 간주하지 않고 제한과 회복
  과정을 명확히 기록한다.

## UC-05. 감당할 수 없는 과부하를 관측한다

- **운영자 목적:** 가용 자원으로 부하를 감당하기 어려운 구간의 요청 결과와 지연을
  확인한다.
- **시스템 반응:** 워크로드별 부하·큐, 요청 수·실제 결과, 지연 분포·백분위, SLO 목표와
  가용 자원을 관측 구간과 함께 제공한다.
- **허용된 개입:** 관측·분석 구간을 선택하고, 허용 자원과 유지보수 제외의 변경은
  정책 변경 절차를 따른다.
- **성공 조건:** 운영자가 요청 결과와 지연을 자원·부하·제어 동작의 시간축에 연결해
  해석하고 그 근거를 찾는다.

## UC-06. 정책 변경을 미리 검증하고 적용한다

- **운영자 목적:** SLO, 허용 자원, 자동화 모드, 여유 용량과 유지보수 제외의 영향을
  적용 전에 확인한다.
- **시스템 반응:** 현재 관측 스냅샷으로 dry-run을 수행해 후보 구성, 용량, 전력,
  전환 필요 여부와 보장 변화를 비교한다. 적용 후에는 비동기 수렴 상태를 제공한다.
- **허용된 개입:** 영향과 보장 변화를 확인한 뒤 사유와 함께 적용하거나 취소한다.
- **성공 조건:** 정책 변경과 실행 결과의 인과관계가 보존되고 예상하지 못한 저수준
  조작이 발생하지 않는다.

## UC-07. 측정 프로파일을 운영 가능 상태로 승격한다

- **운영자 목적:** 새 디바이스, 모델 또는 전력모드 조합의 측정 근거를 검증한다.
- **시스템 반응:** 필요한 측정 조합과 공백을 계산하고, 격리된 측정 실행의 원시 증거와
  품질 결과를 연결한다. 승격된 프로파일로 파생 모델과 구성 후보를 재계산한다.
- **허용된 개입:** 측정을 요청하고 증거를 검토해 프로파일을 승격·거부·폐기하거나
  재측정을 요구한다. 서비스 트래픽과 격리되지 않은 측정은 실행할 수 없다.
- **성공 조건:** 검증되지 않은 조합은 자동 제어 후보가 되지 않으며, 승격된 조합의
  적용 범위와 근거를 추적할 수 있다.
