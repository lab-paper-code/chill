# 운영 모델과 책임 경계

## 시스템 경계

```text
운영자
  ├─ Dashboard
  └─ CLI
        │  동일한 권한·검증·결과 의미
        ▼
CHILL 운영 계약
  ├─ 선언 경로 ──> CHILL API ──> 제어기·실행기 ──> 데이터 플레인
  └─ 조회 경로
       ├─ CHILL desired/status/decision
       ├─ Kubernetes workload·Node·Event
       ├─ 부하·지연·큐·전력·온도 메트릭
       └─ 측정 증거와 프로파일 계보
```

Dashboard와 CLI는 선언된 운영 계약을 통해서만 상태를 변경한다. CHILL 자체의
설치·업그레이드·제거는 Helm이나 GitOps가 담당하는 별도 수명주기이며 런타임 운영
콘솔의 책임이 아니다.

## 운영 역할

| 역할 | 책임과 권한 |
|---|---|
| CHILL 운영자 | SLO와 정책 변경, 자동화 모드 설정, 전환 감독, 유지보수 제외와 안전 대응 |
| 프로파일 관리자 | 측정 요청, 증거 검토, 프로파일 승격·폐기와 재측정 |
| 관찰자·감사자 | 상태와 decision 조회, 감사·재현 자료 내보내기 |

한 사람이 여러 역할을 맡을 수 있지만 각 동작의 권한과 행위자는 구분해 기록한다.

## 운영 모드와 안전 상태

운영 모드는 CHILL이 자동으로 실행할 수 있는 범위를 선언한다.

| 모드 | 동작 |
|---|---|
| Observe | 계산과 설명만 수행하고 데이터 플레인을 변경하지 않는다. |
| Supervised | 사전 승인된 SLO 보호 범위는 자동 실행하고, 경제적 전환은 운영자 승인을 요구한다. |
| Autonomous | 검증된 정책 범위에서 방아쇠, 방어와 전환 사다리를 자동 수행한다. |

안전 상태는 운영자가 선택하는 모드가 아니라 시스템 조건이 강제하는 제어 제한이다.

- **동결(Frozen)**: 관측 신선도가 한계를 넘으면 D1에 따라 T2·T3을 정지하고,
  노드 로컬 큐에 의존하는 T1은 유지한다.
- **열 할인**: D2가 감지한 노드는 실측된 스로틀링 용량으로 평가한다.
- **과부하 저하**: 자격 있는 구성으로 부하를 감당할 수 없으면 명세가 정한 순서와
  운영자가 선언한 대체 모델·클래스 우선순위에 따라 서비스를 단계적으로 저하시킨다.

T1까지 멈추는 emergency stop은 break-glass로만 허용하며 SLO 보호가 꺼졌음을
지속적으로 표시하고 기록한다.

## 명세 층별 운영 책임

계산과 실행 규칙은 CHILL이 소유한다. 운영 표면은 그 근거와 결과를 보여주고,
운영자에게 상위 정책만 허용한다.

| 명세 층 | 운영자가 관찰할 것 | 운영자가 제어할 것 |
|---|---|---|
| 0. 측정 | 조합별 완료도, 품질, 신선도, 증거 identity와 실패 | 측정 요청, 프로파일 승격·폐기, 재측정 |
| 1. 배치 | SLO 예산, 실현된 배치와 p99, 남은 여유 | SLO와 안전 마진. 배치 크기는 직접 지정하지 않음 |
| 2. 전력 곡선 | 근거 프로파일, 유효 범위, 예측·실측 오차 | 프로파일 무효화와 재계산. 곡선은 직접 편집하지 않음 |
| 3. 라우팅 | 노드별 부하·용량·가중치와 선택 이유 | 유지보수 제외와 허용 대상. 가중치는 직접 지정하지 않음 |
| 4. 구성 | 현재·최적·목표 구성, 전력 차이, 용량, 제외 이유 | 허용 노드·모델·전력모드와 여유 정책 |
| 5. 전환 | 방아쇠, 비용·시간, 실행 단계와 중단 가능성 | 자동화 모드, 승인, 하향 전환 중단, 안전 구성 요청 |
| 6. 과부하 | 저하 단계, 클래스별 드롭·위반량과 복귀 조건 | 대체 모델 사슬과 클래스 희생 우선순위. 단계 순서는 변경하지 않음 |
