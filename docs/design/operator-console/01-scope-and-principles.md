# 범위와 설계 원칙

## 범위

이 문서는 [CHILL 시스템 명세](../../spec/README.md)를 구현하는 운영자 콘솔의
범위를 다룬다. 현재 API와 컨트롤러가 명세의 제품 경계를 제한하지 않는다.

여기서 확정하는 것은 화면이나 API 필드가 아니라 능력의 경계다. 운영자가 무엇을
볼 수 있어야 하는지, 무엇을 변경할 수 있는지, 무엇은 직접 변경할 수 없는지를
정의한다.

## 목적

CHILL은 이기종 엣지 클러스터에서 추론 서비스의 지연 목표(SLO)를 지키면서 총 에너지
소비를 줄이는 폐루프 제어 시스템이다. 장비, 모델, 전력모드, 라우팅은 측정 근거와
운영 정책으로부터 시스템이 계산하고 안전하게 전환한다.

운영자 콘솔은 다음을 가능하게 해야 한다.

1. 워크로드별 지연·처리 결과와 SLO 목표, 전체 POOL 에너지를 조회한다.
2. 판단에 사용한 측정값, 모델, 제약, 방아쇠를 확인한다.
3. 측정 프로파일과 운영 정책의 적용 범위를 승인하거나 제한한다.
4. 자동화의 권한과 안전 제약을 선언한다.
5. 전환과 장애에 안전 규칙 안에서 개입하고, 과거 결정을 재구성한다.

> CHILL 운영자 콘솔은 자동 제어기를 원격 조종하는 패널이 아니라, 자동 제어의
> 근거를 검증하고 권한을 부여하며 예외 상황을 안전하게 다루는 운영 표면이다.

## 핵심 개념

알고리즘 용어의 정의는 `docs/spec/`을 따른다. 이 문서에서 별도로 구분해야 하는
운영 개념은 다음과 같다.

| 개념 | 의미 |
|---|---|
| 현재·최적·목표 구성 | 지금 실현된 구성, 계산상 가장 적합한 구성, 진행 중인 전환의 도착지를 서로 다른 상태로 다룬다. |
| 운영 모드·안전 상태 | 운영 모드는 자동화 권한의 선언이고, 안전 상태는 관측이나 시스템 조건 때문에 강제된 제어 제한이다. |
| decision record | 목표 변경, 안전 상태 전이, 전환 시작·중단처럼 운영 결과를 바꾸는 중요 판단의 입력과 근거, 결과를 묶은 기록이다. |
| dry-run | 정책 변경을 현재 관측 상태에 대입해 구성, 용량, 전력, 보장 변화를 적용 전에 계산한다. |
| override·break-glass | 정상 자동화 범위를 일시적으로 제한하거나 안전 규칙 밖에서 비상 조작한다. 사유, 영향, 만료가 반드시 따른다. |

## 설계 원칙

### 선언·관측·파생·판단·실행을 구분한다

콘솔은 성격이 다른 정보를 하나의 상태처럼 섞지 않는다.

| 층 | 내용 | 예시 |
|---|---|---|
| 운영자 선언 | 목표와 허용 범위 | 워크로드별 SLO, 허용 자원, 자동화 모드, 중단 예산 |
| 관측 사실 | 실제로 관측된 값 | 부하, 큐, 요청 수·결과, 지연 분포·백분위, 벽전력, 온도, 신선도 |
| 측정·파생 모델 | 검증된 증거로 계산한 모델 | 실행 시간, 전력 곡선, 용량, 활성 구성 집합 |
| 제어 판단 | 시스템이 내린 선택과 이유 | 방아쇠, 목표 구성, 유지 판단, 안전 상태 |
| 실행 결과 | 데이터 플레인에서 일어난 사실 | 준비, 라우팅, 드레인, 전력모드 변경, 실패 |

각 값에는 층, 생성 시각, 생성 주체와 근거를 식별할 수 있는 정보가 따라야 한다.

### 정상 운영에서 저수준 계산값을 직접 지정하지 않는다

배치 크기, 큐 대기 상한, 라우팅 가중치와 최적 구성은 CHILL이 계산한다. 운영자는
다음과 같은 상위 의도를 선언한다.

- 관리할 워크로드, 모델과 워크로드별 SLO
- 사용할 수 있는 노드, 디바이스 타입, 전력모드와 측정 프로파일
- 여유 용량, 중단 예산과 자동화 허용 범위
- 유지보수 제외 대상

구성 고정이나 가중치 강제는 정상 제어가 아니다. 진단상 필요하다면 제한된 권한,
사유, 영향 미리보기, 만료 시각과 감사 기록을 요구하며 보장 상실을 명시한다.

### 변경은 비동기 desired-state 작업이다

Dashboard와 CLI는 Pod, 라우터, 측정 작업이나 노드 전력모드를 직접 변경하지 않는다.
운영 의도를 선언하면 CHILL이 검증하고 조정한다. 접수, 검증, 실행, 완료와 거부를
서로 다른 작업 상태로 제공한다.

### 원본 상태를 복제해 새로운 진실을 만들지 않는다

CHILL 상태, Kubernetes 상태, 메트릭과 불변 측정 증거는 각자의 권위 있는 원본을
유지한다. 조회 모델은 이를 결합할 수 있지만 별도 복제본을 원본처럼 취급하지 않는다.

### 설명 가능성은 제어 계약이다

중요 판단은 최소한 다음을 설명해야 한다.

- 사용한 입력과 시각, 신선도, 프로파일 버전
- 현재·최적·목표 구성과 제외된 후보의 제약
- 관여한 방아쇠와 안전 상태
- 예상한 전환 시간, 비용과 SLO 영향
- 실제 실행 결과와 예상의 차이
