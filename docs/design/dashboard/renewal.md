# CHILL Dashboard 리뉴얼 설계

상태: 진행 중. 브랜치 `dashboard-renewal`. 이 문서가 새 화면 구조, 화면별 내용, 공통 부품과 작업 규칙을 소유한다.
전송과 인증 경계는 [구현 설계](README.md)의 "아키텍처와 신뢰 경계", "인증과 변경" 절을 그대로 따른다.

## 1. 목표

기존 화면은 서버 객체와 구현 단위를 따라 기능을 덧붙여 왔다. 새 화면은 사용자가 하려는 일에서 출발한다.

| 사용자 | 하려는 일 |
|---|---|
| 운영자 | 지금 모든 서비스가 목표 지연을 지키는지, 어디서 실행되는지, 전력을 얼마나 쓰는지 확인한다 |
| 운영자 | 스케줄러가 무엇을 왜 결정했는지 확인하고 설정을 바꾼다 |
| 운영자 | 서비스, 모델, 전처리기, 데이터셋을 등록하고 고친다 |
| 측정 담당자 | 어떤 조합이 측정되었는지 보고, 빠진 조합을 요청하고, 결과와 실패 원인을 본다 |
| 실험 담당자 | 실험을 정의하고 실행하고, 결과를 비교한다 |

## 2. 화면 원칙

1. 한 화면은 한 가지 질문에 답한다. 화면 구성은 요약 한 줄, 주 영역 하나, 보조 영역 하나까지다.
2. 설명 문장을 화면에 두지 않는다. 이름표, 값, 단위만 둔다. 뜻풀이가 필요하면 정보 아이콘의 툴팁에 한 문장으로 둔다.
3. 원본 JSON, UID, 이미지 digest는 기본 화면에 없다. 원본은 더보기 메뉴의 "원본 보기" 대화상자에서, 식별자는 복사 버튼이 달린 짧은 표기로 본다.
4. 표는 일곱 열 이하다. 나머지 값은 행을 눌러 여는 상세에서 본다.
5. 목록에서 상세로 갈 때는 페이지를 이동한다. 상세 페이지는 탭으로 나눈다. 서랍은 행 미리보기에만 쓰고 겹치지 않는다. 대화상자는 확인과 짧은 입력에만 쓴다.
6. 화면마다 주 동작은 머리글 오른쪽에 하나다. 삭제 같은 위험 동작은 더보기 메뉴에 둔다.
7. 값이 없으면 "—"를 보이고 툴팁에 사유를 둔다. 조회 실패와 권한 없음은 영역 단위 오류 상태로 따로 보인다.
8. 시각은 한국 표준시다. 실시간 화면은 "3분 전" 같은 상대 표기와 툴팁의 절대 시각을 쓴다. 기록 표는 절대 시각을 쓴다.
9. 숫자는 고정폭 숫자, 오른쪽 정렬이며 단위는 열 머리글에 둔다.
10. 판정과 통계는 서버 값만 보인다. 브라우저는 단위 변환과 서버 값 사이의 차이 표시까지만 한다. 전력 적분, 분위수 평균, 빈 구간 보간을 하지 않는다.
11. 변경은 대상, 변경 전후, 영향을 보인 뒤 확정한다. 응답을 받지 못하면 "결과 미확인"으로 두고 자동으로 다시 보내지 않는다.

## 3. 화면 구조

```text
운영
  개요            /
  서비스          /services
  장치            /devices
  스케줄러        /scheduler
분석
  측정            /measurements
  실험            /experiments
관리
  카탈로그        /catalog
```

| 주소 | 화면 |
|---|---|
| `/` | 개요 |
| `/services` | 서비스 목록 |
| `/services/new`, `/services/[name]/edit` | 서비스 등록, 수정 |
| `/services/[name]` | 서비스 상세. 탭: 현황, 요청, 정의, 테스트 (`?tab=`) |
| `/devices` | 장치 목록과 전체 전력 |
| `/devices/[name]` | 장치 상세 |
| `/scheduler/decisions` | 판단 기록 |
| `/scheduler/actions` | 변경 작업 기록 |
| `/scheduler/settings` | 스케줄러 설정 |
| `/measurements/coverage` | 측정 범위 |
| `/measurements/requests` | 측정 요청 목록 |
| `/measurements/requests/new` | 측정 요청 작성 |
| `/measurements/requests/[name]` | 측정 요청 상세 |
| `/measurements/runs/[name]` | 측정 회차 상세 |
| `/measurements/results` | 측정 결과. 종류: 처리 성능, 전환 비용, 분배 점유시간 (`?kind=`) |
| `/experiments/runs` | 실험 실행 목록 |
| `/experiments/runs/new`, `/experiments/runs/[name]/edit` | 실험 작성, 수정 |
| `/experiments/runs/[name]` | 실험 실행 상세 |
| `/experiments/results` | 게시된 결과 목록 |
| `/experiments/results/[id]` | 결과 상세 |
| `/experiments/scenarios` | 부하 시나리오 목록 |
| `/experiments/scenarios/new`, `/experiments/scenarios/[name]/edit` | 부하 시나리오 작성, 수정 |
| `/catalog/models`, `/catalog/preprocessors`, `/catalog/datasets` | 카탈로그 목록 |
| `/catalog/[kind]/new`, `/catalog/[kind]/[name]/edit` | 카탈로그 등록, 수정 |
| `/catalog/[kind]/[name]` | 카탈로그 상세 |

`/scheduler`, `/measurements`, `/experiments`, `/catalog`은 첫 탭으로 이동한다. 예전 주소의 이동 규칙은 두지 않는다.

기존 "기록" 메뉴는 없앤다. 기록은 그 대상의 화면에 둔다.

| 기록 | 위치 |
|---|---|
| 스케줄러 판단 | 스케줄러 > 판단 |
| 변경 작업 | 스케줄러 > 작업 |
| 설정 변경 | 스케줄러 > 설정 > 변경 이력 |
| 서비스 요청 | 서비스 상세 > 요청 |
| 서비스 정의 변경 | 서비스 상세 > 정의 > 변경 이력 |
| 전력 | 장치, 장치 상세 |

## 4. 공통 틀

- 왼쪽 사이드바: 위 구조의 일곱 항목. 아이콘만 남기고 접을 수 있다.
- 위 머리줄: 현재 위치, 실시간 연결 상태, 진행 중 표시(실행 중인 실험, 진행 중인 측정), 검색 창, 테마 전환, 계정 메뉴.
- 검색 창(Ctrl K): 화면, 서비스, 장치, 모델 이름으로 바로 이동한다.
- 계정 메뉴: 접속 대상, 네임스페이스, "이 탭에서 토큰 지우기".
- 페이지 머리글: 제목, 상태 배지, 주 동작, 더보기 메뉴. 그 아래 탭.
- 로그인 화면: 토큰 입력 하나.

## 5. 시각 체계

| 항목 | 결정 |
|---|---|
| 글꼴 | Pretendard Variable. 저장소에 포함한 파일을 `next/font/local`로 쓴다. 숫자는 `tabular-nums` |
| 기본 글자 | 14px. 표 행 높이 40px |
| 모서리 | 카드 10px, 입력과 버튼 6px |
| 깊이 | 그림자를 쓰지 않고 1px 테두리로 구분한다 |
| 테마 | 밝은 테마와 어두운 테마. 시스템 설정을 따르고 머리줄에서 바꾼다 |
| 움직임 | 사용자 동작에 답하는 전환만 둔다. 1초마다 갱신되는 값에는 등장 효과와 숫자 세기 효과를 쓰지 않는다 |

색은 뜻을 전한다.

| 토큰 | 밝은 테마 | 어두운 테마 | 쓰임 |
|---|---|---|---|
| `--background` | `#F5F6F8` | `#0F1318` | 바탕 |
| `--card` | `#FFFFFF` | `#171C23` | 표면 |
| `--foreground` | `#1B2430` | `#E6EAF0` | 글자 |
| `--muted-foreground` | `#5B6675` | `#98A2B3` | 보조 글자 |
| `--border` | `#E3E6EB` | `#252C36` | 테두리 |
| `--primary` | `#1F5FD6` | `#6FA0FF` | 주 동작, 선택, 연결 |
| `--ok` | `#1F8A5B` | `#4CC38A` | 목표 충족, 준비됨, 완료 |
| `--warn` | `#B7791F` | `#E2A93B` | 주의, 진행 중인 변경 |
| `--fail` | `#D13B2E` | `#FF6B5E` | 목표 초과, 실패 |
| `--idle` | `#8A94A3` | `#6B7684` | 유휴, 값 없음 |

차트 계열 색은 상태 색과 겹치지 않게 따로 둔다: `#1F5FD6`, `#0FA3A3`, `#7C5CFA`, `#D97A2B`, `#C2417A`, `#64748B`.

지연 여유 막대가 이 대시보드의 고유 표현이다. 관측 지연을 목표 지연에 대한 비율로 그리고, 여유가 클수록 차가운 색(`--primary`), 목표에 가까울수록 따뜻한 색(`--warn`), 넘으면 `--fail`로 칠한다. 충족 판정 글자는 서버 값만 쓴다.

상태는 색과 함께 모양과 글자로도 전한다.

## 7. 화면별 설계

각 화면의 "자료"는 ChillServer 경로다. 브라우저는 `/api/chill/` 뒤에 같은 경로를 붙여 부른다.

### 7.1 개요 `/`

질문: 지금 괜찮은가.

- 요약 줄(타일 넷): 서비스(목표 충족 수와 판정 가능한 수), 유입(전체 req/s), 전력(활성 풀과 전체 풀 W), 스케줄러(마지막 판단 시각과 결과, 자동 제어 중인 서비스 수).
- 주 영역: 서비스 표. 열: 상태, 서비스, 유입(req/s와 최근 60초 추이), 지연(설정 분위수 값과 목표, 여유 막대), 성공률, 배치(인스턴스 수와 장치 이름), 자동 제어. 행을 누르면 서비스 상세로 간다. 기본 정렬은 이름순이며 값이 바뀌어도 순서를 바꾸지 않는다.
- 보조 영역: "진행 중"(변경 작업, 측정, 실험)과 "최근 활동"(변경, 장애, 설정 변경. 유지 판단은 건수만 보인다). 항목을 누르면 스케줄러의 해당 기록으로 간다.
- 아래: 전체 전력 추이 15분.
- 자료: 실시간 스트림(구성, 초당 지표, 사건), `v1/scheduler/state?view=summary`, `v1/observations/events`, `v1/observations/power`(구간 묶음), `v1/evaluations/active`.

### 7.2 서비스

목록 `/services`

- 표. 열: 상태, 서비스, 모델, 목표(분위수와 지연), 접수, 자동 제어, 변경 작업. 검색과 상태 구간 선택.
- 주 동작: 서비스 등록.
- 자료: `v1/workloads?view=summary`, `v1/scheduler/settings`.

상세 `/services/[name]`

- 머리글: 이름, 준비 상태, 접수 상태, 자동 제어 스위치. 주 동작: 수정. 더보기: 삭제, 원본 보기.
- 현황 탭: 타일(유입, 지연과 목표, 성공률, 대기). 최근 5분 유입과 지연 시계열. 배치 표(인스턴스, 장치, 전력 모드, 분배 비율, 처리 중, 대기). 배치 표의 동작 "분배 수정"은 대화상자에서 인스턴스별 가중치를 바꾸고 사유를 받는다.
- 요청 탭: 구간과 결과 선택. 요청 표(시각, 결과, 소요 시간, 장치, 배치). 행 미리보기에 단계별 시간 막대.
- 정의 탭: 정의 목록(모델, 전처리기, 데이터셋, 목표, 과부하 정책, 대기 상한, 최종 기한), 적용 상태, 변경 이력.
- 테스트 탭: 입력 폼과 전송. 결과와 단계별 시간. 한 번만 보내고 자동으로 다시 보내지 않는다.
- 자동 제어 스위치와 분배 수정은 확인 대화상자를 거친다.
- 자료: `v1/workloads/{name}`, 실시간 스트림, `v1/pools`, `v1/observations/workloads/{uid}`, `v1/scheduler/settings`(자동 제어), `v1/scheduler/operations`(분배), `v1/workloads/{name}/infer`.

등록과 수정

- 한 페이지 폼. 구획: 이름, 모델, 전처리기, 데이터셋, 응답 목표, 과부하 정책. 오른쪽에 입력 요약. 아래 줄에 검토와 제출.
- 수정은 변경 전후를 검토 대화상자에 보인다.
- 자료: `v1/workloads`, `v1/models`, `v1/preprocessors`, `v1/datasets`.

### 7.3 장치

목록 `/devices`

- 위: 전체 전력 시계열과 구간 선택(15분, 1시간). 타일: 전체 풀 W, 활성 풀 W, 구간 에너지 J(서버 적분 값).
- 표. 열: 장치, 종류, 역할(서비스, 측정, 가용, 제외), 준비, 전력 모드, 전력(W와 막대), 서비스.
- 자료: 실시간 스트림, `v1/pools`, `v1/inventory`, `v1/scheduler/state?view=summary`, `v1/observations/power`.

상세 `/devices/[name]`

- 머리글: 이름, 준비, 역할.
- 타일: 현재 전력, 전력 모드, 인스턴스 수.
- 전력 시계열. 인스턴스 표(서비스, 분배 비율, 처리 중, 대기). 사양 목록(종류, 아키텍처, 메모리, 가속기)과 전력 모드 표.

### 7.4 스케줄러

판단 `/scheduler/decisions`

- 위: 판단 소요 시간 막대 차트(판단마다 하나)와 설정된 판단 주기 선.
- 왼쪽 목록: 시각, 결과(유지, 변경), 사유. 기본은 변경만 보이며 유지 판단을 포함하는 스위치가 있다. 구간 선택.
- 오른쪽 상세: 결과와 사유, 유지안과 변경안 비교(예상 에너지, 서비스별 예상 지연과 목표), 서비스별 자동 제어 상태, 입력 수요. 더보기: 원본 보기.
- 두 판단 비교: 목록에서 둘을 고르면 비교 대화상자가 항목별 차이를 보인다.
- 자료: `v1/observations/scheduler`(요약 보기, 단건), `v1/scheduler/settings`.

작업 `/scheduler/actions`

- 표. 열: 시작, 동작, 장치, 서비스, 상태, 소요. 상태와 구간 선택.
- 행 미리보기: 계획과 실제, 오류.
- 자료: `v1/observations/scheduler?filter=action`, `v1/scheduler/state?view=summary`(진행 중).

설정 `/scheduler/settings`

- 구획 카드: 대상(자동 제어 서비스, 최소 수요, 제외 장치, 우선순위), 판단 주기와 비교 기간, 자원 한도, 자동 조정 항목(스위치 일곱), 용량 계산, 탐색(접힘).
- 모든 값은 제자리에서 고친다. 고친 값에 표시가 붙고 아래 줄이 "변경 n건"과 "검토 후 적용"을 보인다. 검토 대화상자는 변경 전후 표를 보인다.
- 저장은 조회 때 받은 버전을 조건으로 보낸다. 충돌하면 최신 값과 내 변경을 나란히 보인다.
- 변경 이력: 아래 접힌 구획에 최근 설정 변경 표.
- 자료: `v1/scheduler/settings`(조회, 저장), `v1/workloads?view=summary`, `v1/pools`, `v1/observations/scheduler?filter=settings`.

### 7.5 측정

범위 `/measurements/coverage`

- 요약 줄: 측정된 조합과 지원 조합, 스케줄러가 쓰는 조합, 실패, 진행 중.
- 모델 구간 선택. 행렬: 행은 장치 종류와 전력 모드, 열은 실행 경로. 칸은 상태 점과 측정된 배치 수.
- 칸 미리보기: 상태, 배치별 결과 표(배치, 지연, 건당 에너지), 실패 사유, 동작 "이 조건으로 측정 요청", "요청 기록".
- 자료: `v1/namespaces/{ns}/measurement-coverage`, `v1/inventory`.

요청 `/measurements/requests`

- 표. 열: 요청, 대상(모델, 장치, 전력 모드, 실행 경로), 상태, 완료 회차, 생성. 상태 구간 선택과 검색.
- 주 동작: 측정 요청.
- 자료: `v1/namespaces/{ns}/batch-energy-optimizations`.

요청 상세 `/measurements/requests/[name]`

- 머리글: 이름, 상태. 주 동작: 같은 조건으로 요청. 더보기: 삭제, 요청 문서 내려받기, 원본 보기.
- 탭: 결과(배치별 표와 CSV), 회차(표. 행을 누르면 회차 상세), 조건(목록), 실패(실패했을 때만. 원인, 종료 코드, 연결 회차).
- 자료: `v1/namespaces/{ns}/batch-energy-optimizations/{name}/result`, `v1/namespaces/{ns}/profiling-runs?parentUID=`.

회차 상세 `/measurements/runs/[name]`

- 타일: 처리량, 지연 분위수, 평균 전력. 조건 목록. 배치 실행 표. 실행 로그는 접힌 구획.
- 자료: `v1/namespaces/{ns}/profiling-runs`, 증거 요약 경로.

요청 작성 `/measurements/requests/new`

- 종류 선택: 프로파일, 분배 점유시간. 방법 선택: 폼, 문서 가져오기.
- 프로파일 폼은 세 단계: 대상(서비스, 장치, 실행 경로, 전력 모드), 조건(측정 방식 값. 고급 값은 접힘), 검토(사전 검사 결과와 제출).
- 분배 점유시간 폼은 한 단계: 측정 칸, 서비스, 배치, 이름. 검사 뒤 제출.
- 범위 화면의 칸에서 오면 대상이 채워져 있다.
- 자료: `v1/models`, `v1/workloads?view=summary`, `v1/inventory`, `v1/model-compatibility`, 사전 검사와 제출 경로.

결과 `/measurements/results`

- 종류 구간 선택: 처리 성능, 전환 비용, 분배 점유시간.
- 처리 성능 표. 열: 모델, 장치와 조건, 대표 배치, 지연, 건당 에너지, 사용 여부, 측정일. 미리보기: 배치별 표와 조건.
- 전환 비용 표. 열: 모델, 장치, 동작, 시간 중앙값, 에너지 중앙값, 표본 수, 상태. 미리보기: 동작별 범위.
- 분배 점유시간 표. 열: 측정, 장치, 서비스, 배치, 점유시간 중앙값, 상태. 미리보기: 분포와 조건. 더보기: 삭제.
- 자료: `v1/scheduler/profiles`, `v1/namespaces/{ns}/operation-cost-measurements`, `v1/namespaces/{ns}/dispatch-occupancy-measurements`.

### 7.6 실험

실행 `/experiments/runs`

- 실행 중인 실험이 있으면 위에 진행 카드(단계, 경과, 남은 시간).
- 표. 열: 이름, 상태, 단계, 시작, 종료, 결과(게시 결과로 가는 링크).
- 주 동작: 새 실험.
- 자료: `v1/evaluations`, `v1/evaluations/active`.

실행 상세 `/experiments/runs/[name]`

- 머리글: 이름, 상태, 판정. 주 동작: 결과 보기(게시된 경우). 더보기: 수정(시작 전), 다시 실행, 중지 또는 삭제, 원본 보기.
- 탭: 진행(절차 단계 표시와 현재 단계의 잠정 결과), 계획(단계와 부하 표, 설정 변경), 정리(풀 반환 상태와 반환 확인 요청), 대상(구성요소와 이미지).
- 자료: `v1/evaluations/{name}`, `v1/evaluations/active`, `v1/experiments/{id}`.

결과 목록 `/experiments/results`

- 표. 열: 실험, 기간, 판정, 단계 수, 비교. 페이지 넘김.
- 자료: `v1/experiments`.

결과 상세 `/experiments/results/[id]`

- 머리글: 이름, 게시 판정, 목표를 못 지킨 서비스. 주 동작: 다시 실행.
- 단계 선택. 비교 쌍이 있으면 기준 단계 선택.
- 탭: 요약(서비스별 카드: 판정, 기한 내 성공률, 유효 처리량, 지연 분위수. 에너지와 평균 전력. 비교 쌍이 있으면 차이 값), 추이(요청률, 지연, 에너지 차트), 요청 결과(서비스별 결과 분류와 대기, 거절 표), 에너지(노드별 계측 표), 조건(비교 조건, 측정 규칙, 정의 출처).
- 자료: `v1/experiments/{id}`.

작성 `/experiments/runs/new`

- 구획 탭: 기본(이름, 질문, 부하 발생 장치), 단계(단계 목록. 단계마다 부하 시나리오와 설정 변경), 비교, 판정 기준. 오른쪽에 사전 점검 결과와 제출.
- 시작점: 빈 양식, 기존 실행 복사, 게시 결과 복사.
- 정의 전체를 JSON으로 보고 고치는 전환이 있다.
- 자료: `v1/evaluations/template`, `v1/evaluations/load-scenarios`, `v1/evaluations/preflight`, `v1/evaluations`.

부하 시나리오 `/experiments/scenarios`

- 표. 열: 이름, 구간 수, 전체 길이, 서비스, 사용 중, 생성. 주 동작: 새 시나리오.
- 작성 폼: 이름, 구간 표(길이, 서비스별 요청률), 도착 분포. 요청률 미리보기 차트.
- 자료: `v1/evaluations/load-scenarios`.

### 7.7 카탈로그

목록 `/catalog/[kind]`

- 탭: 모델, 전처리기, 데이터셋. 표. 열: 이름, 요약(모델은 파일 형식과 실행 경로 수, 전처리기는 입출력, 데이터셋은 필드), 사용하는 서비스 수.
- 주 동작: 등록.

상세 `/catalog/[kind]/[name]`

- 머리글: 이름. 주 동작: 수정. 더보기: 삭제, 원본 보기.
- 정의 목록과 표(모델은 파일과 실행 경로). 사용하는 서비스 표.

등록과 수정

- 한 페이지 폼과 "문서 가져오기" 탭(YAML 또는 JSON). 반복 항목(파일, 실행 경로, 필드)은 추가와 삭제가 되는 행 편집기.
- 자료: `v1/models`, `v1/preprocessors`, `v1/datasets`.
