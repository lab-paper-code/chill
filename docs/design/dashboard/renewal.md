# CHILL Dashboard 리뉴얼 설계

상태: 진행 중. 브랜치 `dashboard-renewal`. 이 문서가 새 화면 구조, 화면별 내용, 공통 부품과 작업 규칙을 소유한다.
전송과 인증 경계는 [구현 설계](README.md)의 "아키텍처와 신뢰 경계", "인증과 변경" 절을 그대로 따른다.

## 1. 목표

기존 화면은 서버 객체와 구현 단위를 따라 기능을 덧붙여 왔다. 새 화면은 사용자가 하려는 일에서 출발한다.

| 사용자 | 하려는 일 |
|---|---|
| 운영자 | 지금 모든 서비스가 목표 지연을 지키는지, 어디서 실행되는지, 전력을 얼마나 쓰는지 확인한다 |
| 운영자 | 스케줄러가 무엇을 왜 결정했는지, 판단 주기를 지키는지 확인하고 설정을 바꾼다 |
| 운영자 | 서비스, 모델, 전처리기, 데이터셋을 등록하고 고친다 |
| 측정 담당자 | 어떤 조합이 측정되었는지 보고, 빠진 조합을 요청하고, 결과와 실패 원인을 본다 |
| 실험 담당자 | 실험을 정의하고 실행하고, 결과를 비교한다 |

이 설계는 [Dashboard 명세](../../spec/dashboard/SRS.md)의 화면 구조와 다르다. 다른 점: 기록과 설정 메뉴를 없애고 대상별 화면에 나눠 둔다. 예전 주소의 이동 규칙을 두지 않는다. 용어 도움말 화면 대신 툴팁을 쓴다. 글꼴을 바꾼다. 명세는 구현이 끝난 뒤 이 문서에 맞춘다.

## 2. 화면 원칙

1. 한 화면은 한 가지 질문에 답한다. 화면 구성은 요약 한 줄, 주 영역 하나, 보조 영역 하나까지다.
2. 설명 문장을 화면에 두지 않는다. 이름표, 값, 단위만 둔다. 뜻풀이가 필요하면 정보 아이콘의 툴팁에 한 문장으로 둔다.
3. 원본 JSON, UID, 이미지 digest는 기본 화면에 없다. 원본은 더보기 메뉴의 "원본 보기" 대화상자에서, 식별자는 복사 버튼이 달린 짧은 표기로 본다.
4. 표는 일곱 열 이하이고 한 칸에 값 하나를 한 줄로 둔다. 나머지 값은 행을 눌러 여는 상세에서 본다.
5. 목록에서 상세로 갈 때는 페이지를 이동한다. 상세 페이지는 탭으로 나눈다. 서랍은 행 미리보기에만 쓰고 겹치지 않는다. 대화상자는 확인과 짧은 입력에만 쓴다. 스케줄러 판단은 목록과 상세를 한 화면에 나란히 둔다.
6. 화면마다 주 동작은 머리글 오른쪽에 하나다. 삭제 같은 위험 동작은 더보기 메뉴에 두고 확인 대화상자를 거친다.
7. 값이 없으면 "—"를 보이고 툴팁에 사유를 둔다. 조회 실패와 권한 없음은 영역 단위 오류 상태로 따로 보인다.
8. 시각은 한국 표준시다. 실시간 화면은 "3분 전" 같은 상대 표기와 툴팁의 절대 시각을 쓴다. 기록 표는 절대 시각을 쓴다.
9. 숫자는 고정폭 숫자, 오른쪽 정렬이며 단위는 열 머리글에 둔다.
10. 판정과 통계는 서버가 계산한 값만 보인다. 브라우저는 단위 변환, 서버 값의 합과 개수, 두 서버 값의 비율과 차이, 서버 값과 서버 목표의 비교 표시까지 한다. 분위수 계산, 전력 적분, 빈 구간 보간, 판정 기준 만들기를 하지 않는다.
11. 변경은 대상, 변경 전후, 영향을 보인 뒤 확정한다. 응답을 받지 못하면 "결과 미확인"으로 두고 자동으로 다시 보내지 않는다. 작성 중인 폼을 떠날 때는 확인을 받는다.
12. 서버 코드는 화면에 그대로 나오지 않는다. 한국어 이름표로 바꾸고, 모르는 코드는 "—"와 툴팁의 코드로 보인다.

## 3. 화면 구조

```text
운영
  개요            /
  서비스          /services
  장치            /devices
  스케줄러        /scheduler
분석
  측정            /measurements
  실험            /experiments
관리
  카탈로그        /catalog
```

| 주소 | 화면 |
|---|---|
| `/` | 개요 |
| `/services` | 서비스 목록 |
| `/services/new`, `/services/[name]/edit` | 서비스 등록, 수정 |
| `/services/[name]` | 서비스 상세. 탭: 현황, 요청, 정의, 테스트 (`?tab=`) |
| `/devices` | 장치 목록과 전체 전력 |
| `/devices/[name]` | 장치 상세 |
| `/scheduler/decisions` | 판단 기록 |
| `/scheduler/actions` | 작업, 예약, 사건 |
| `/scheduler/settings` | 스케줄러 설정 |
| `/measurements/coverage` | 측정 범위 |
| `/measurements/requests` | 측정 요청 목록 |
| `/measurements/requests/new` | 측정 요청 작성 |
| `/measurements/requests/[name]` | 측정 요청 상세 |
| `/measurements/runs/[name]` | 측정 회차 상세 |
| `/measurements/results` | 측정 결과. 종류: 처리 성능, 전환 비용, 분배 점유시간 (`?kind=`) |
| `/experiments/runs` | 실험 실행 목록 |
| `/experiments/runs/new`, `/experiments/runs/[name]/edit` | 실험 작성, 수정 |
| `/experiments/runs/[name]` | 실험 실행 상세 |
| `/experiments/results` | 게시된 결과 목록 |
| `/experiments/results/[id]` | 결과 상세 |
| `/experiments/scenarios` | 부하 시나리오 목록 |
| `/experiments/scenarios/[name]` | 부하 시나리오 상세 |
| `/experiments/scenarios/new`, `/experiments/scenarios/[name]/edit` | 부하 시나리오 작성, 수정 |
| `/catalog/models`, `/catalog/preprocessors`, `/catalog/datasets` | 카탈로그 목록 |
| `/catalog/[kind]/new`, `/catalog/[kind]/[name]/edit` | 카탈로그 등록, 수정 |
| `/catalog/[kind]/[name]` | 카탈로그 상세 |

`/scheduler`, `/measurements`, `/experiments`, `/catalog`은 첫 화면으로 이동한다. 같은 메뉴의 화면들은 한 줄의 탭을 함께 쓴다: 스케줄러는 판단, 작업, 설정. 측정은 범위, 요청, 결과. 실험은 실행, 결과, 부하 시나리오. 카탈로그는 모델, 전처리기, 데이터셋.

상세, 수정 주소는 `?uid=`를 받는다. 같은 이름으로 다시 등록된 대상을 잘못 바꾸지 않도록, 주소의 UID와 조회한 UID가 다르면 변경 동작을 막는다.

기록은 그 대상의 화면에 둔다.

| 기록 | 위치 |
|---|---|
| 스케줄러 판단 | 스케줄러 > 판단 |
| 변경 작업, 예약, 클러스터 사건 | 스케줄러 > 작업 |
| 설정 변경 | 스케줄러 > 설정 > 변경 이력 |
| 서비스 요청 | 서비스 상세 > 요청 |
| 서비스 정의 변경 | 서비스 상세 > 정의 > 변경 이력 |
| 전력 | 장치, 장치 상세 |

## 4. 공통 틀

- 왼쪽 사이드바: 위 구조의 일곱 항목. 아이콘만 남기고 접을 수 있다.
- 위 머리줄: 현재 위치(상세, 작성, 수정 화면에서만), 실시간 상태, 진행 중 표시(실행 중인 실험, 측정 중인 장치), 검색 창, 테마 전환, 계정 메뉴.
- 실시간 상태를 누르면 연결 상태, 마지막 수신 시각, 일시정지와 다시 시작, 끊겼을 때의 다시 연결, 서버 연결과 서버 초기화 상태가 보인다.
- 검색 창(Ctrl K): 화면, 서비스, 장치(제외한 장치 포함), 모델, 전처리기, 데이터셋, 실험 실행과 결과, 부하 시나리오 이름으로 바로 이동한다. 측정 요청은 입력한 말로 요청 목록을 여는 동작 하나를 낸다. 목록은 검색 창을 열 때 읽는다.
- 계정 메뉴: 접속 대상, 네임스페이스, "이 탭에서 토큰 지우기".
- 페이지 머리글: 제목, 상태 배지, 주 동작, 더보기 메뉴. 그 아래 탭.
- 로그인 화면: 토큰 입력 하나.

## 5. 시각 체계

| 항목 | 결정 |
|---|---|
| 글꼴 | Pretendard Variable. 저장소에 포함한 파일을 `next/font/local`로 쓴다. 숫자는 `tabular-nums` |
| 기본 글자 | 14px. 표 행 높이 40px |
| 모서리 | 카드 10px, 입력과 버튼 6px |
| 깊이 | 그림자를 쓰지 않고 1px 테두리로 구분한다 |
| 테마 | 밝은 테마와 어두운 테마. 시스템 설정을 따르고 머리줄에서 바꾼다 |
| 움직임 | 사용자 동작에 답하는 전환만 둔다. 1초마다 갱신되는 값에는 등장 효과와 숫자 세기 효과를 쓰지 않는다 |

색은 뜻을 전한다.

| 토큰 | 밝은 테마 | 어두운 테마 | 쓰임 |
|---|---|---|---|
| `--background` | `#F5F6F8` | `#0F1318` | 바탕 |
| `--card` | `#FFFFFF` | `#171C23` | 표면 |
| `--foreground` | `#1B2430` | `#E6EAF0` | 글자 |
| `--muted-foreground` | `#5B6675` | `#98A2B3` | 보조 글자 |
| `--border` | `#E3E6EB` | `#252C36` | 테두리 |
| `--primary` | `#1F5FD6` | `#6FA0FF` | 주 동작, 선택, 진행 |
| `--ok` | `#1F8A5B` | `#4CC38A` | 목표 충족, 준비됨, 완료 |
| `--warn` | `#B7791F` | `#E2A93B` | 주의 |
| `--fail` | `#D13B2E` | `#FF6B5E` | 목표 초과, 실패 |
| `--idle` | `#8A94A3` | `#6B7684` | 유휴, 값 없음 |

차트 계열 색은 상태 색과 겹치지 않게 따로 둔다: `#1F5FD6`, `#0FA3A3`, `#7C5CFA`, `#D97A2B`, `#C2417A`, `#64748B`.

상태 표시는 다섯 가지다: 정상(`--ok`), 주의(`--warn`), 실패(`--fail`), 진행(`--primary`), 유휴(`--idle`). 색과 함께 모양과 글자로도 전한다. 서버 코드와 이름표의 대응은 `lib/status-labels.ts` 한 곳에 둔다.

지연 여유 막대가 이 대시보드의 고유 표현이다. 관측 지연을 목표 지연에 대한 비율로 그린다. 비율이 0.7 미만이면 `--primary`, 0.7 이상 1.0 이하면 `--warn`, 1.0을 넘으면 `--fail`로 칠한다. 색은 표시일 뿐이며 충족 판정 글자는 서버 값을 쓴다.

## 6. 부품

Avara UI 레지스트리의 부품을 먼저 쓴다. Avara에 없는 기본 부품만 shadcn/ui에서 가져온다. 선택형 항목의 디자인은 이 문서의 시각 체계에 맞는 가장 차분한 것을 고른다.

| 쓰임 | 부품 |
|---|---|
| 사이드바 | Avara `sidebar` |
| 탭 | Avara `vertical-tabs`의 가로 알약 형태 |
| 표, 페이지 넘김 | Avara `table`의 표 모양과 `pagination`. 정렬과 페이지 상태는 `@tanstack/react-table` |
| 카드, 버튼, 입력, 선택, 폼 | Avara `card`, `button`, `input`, `select`, `form` |
| 대화상자, 서랍, 팝오버, 툴팁 | Avara `dialog`, `drawer`, `popover`, `tooltip` |
| 알림 | Avara `toast`, `alert` |
| 불러오는 중 | Avara `skeleton`, `loader`, `progress` |
| 현재 위치, 검색 창 | Avara `breadcrumb`, `command`, `kbd` |
| 단계 진행, 시간순 목록 | Avara `stepper`, `timeline` |
| 구간 선택, 날짜 범위 | Avara `toggle-group`, `range-date-picker` |
| 접기, 복사, 테마, 스크롤 | Avara `accordion`, `collapsible`, `copy-button`, `theme-switcher`, `scroll-area` |
| 막대, 도넛 차트 | Avara `chart` |
| 404, 오류 화면 | Avara `not-found`, `error` |
| 체크박스, 라디오, 스위치, 여러 줄 입력, 이름표, 배지, 드롭다운 메뉴 | shadcn/ui |
| 빈 구간이 있는 시계열 | Avara `chart`가 빈 구간과 900개 점을 다루지 못하면 `recharts` |

화면은 아래 공용 부품(`components/kit/`)으로만 조립한다. 화면 파일에서 색, 간격, 표 모양을 새로 정하지 않는다. 사용법은 `chill-dashboard/components/kit/README.md`에 있다.

| 부품 | 역할 |
|---|---|
| `PageHeader`, `PageTabs` | 제목, 배지, 주 동작, 더보기 메뉴, 탭 |
| `StatTile` | 이름표, 값, 단위, 보조 값 하나 |
| `StatusBadge`, `StatusDot` | 상태 다섯 가지 |
| `HeadroomBar` | 지연 여유 막대 |
| `DataTable` | 정렬, 서버 페이지 넘김, 빈 상태, 행 선택, 내려받기. 좁은 화면에서는 행을 이름표와 값의 줄로 쌓거나(`narrow="stack"`, 기본) 첫 열을 고정하고 옆으로 넘긴다(`narrow="scroll"`) |
| `QueryBoundary` | 불러오는 중, 오류, 권한 없음, 초기화 중 |
| `EmptyState` | 빈 상태와 다음 동작 |
| `DetailDrawer` | 행 미리보기 |
| `ConfirmDialog` | 위험 동작 확인, 사유 입력 |
| `RawDialog` | 원본 JSON 보기, 복사, 내려받기 |
| `IdText` | 긴 식별자의 짧은 표기와 복사 |
| `TimeText` | 시각. 목록은 "MM-DD HH:mm:ss", 상세는 연도 포함, 최근성이 요점인 곳만 상대 시각 |
| `TimeRange` | 화면이 허용한 구간(최근 15분, 1시간, 24시간, 직접 선택) |
| `TimeSeries`, `Sparkline` | 시계열. 빈 구간은 잇지 않는다 |
| `Fields` | 이름표와 값의 목록 |
| `FormSection`, `FormActions`, `LeaveGuard` | 폼 구획, 검토와 제출 줄, 떠날 때 확인 |
| `FilterBar` | 검색, 구간 선택, 선택 상자 |
| `Dialog` | 확인이 아닌 내용의 대화상자. 폼 제출과 처리 중 잠금 |

화면에 보이는 말과 형식은 세 모듈이 한 번씩만 정한다. 화면은 직접 만들지 않는다.

| 모듈 | 맡는 것 |
|---|---|
| `lib/status-labels.ts` | 상태, 판정, 사유, 서버 오류 코드의 말. 모르는 코드는 "기타"로 보이고 원래 코드는 툴팁에 남는다 |
| `lib/display-labels.ts` | 장치 종류, 전력 모드, 실행 경로, 아키텍처의 표기. 장치 이름은 식별자라 그대로 보인다 |
| `lib/format.ts` | 소요 시간("55.8초", "1분 28초"), 지연과 목표("p95 1,000 ms"), 전력, 요청률, 성공률, 날짜 |

## 7. 화면별 설계

각 화면의 "자료"는 ChillServer 경로다. 브라우저는 `/api/chill/` 뒤에 같은 경로를 붙여 부른다. `{ns}`는 설정된 네임스페이스다.

### 7.1 개요 `/`

질문: 지금 괜찮은가.

- 요약 줄(타일 넷)
  - 서비스: 목표를 충족한 수와 판정된 수. 누르면 서비스 목록.
  - 유입: 전체 req/s.
  - 전력: 활성 풀 W와 전체 풀 W, 준비된 장치 수. 누르면 장치.
  - 스케줄러: 마지막 판단 시각과 결과, 자동 제어 중인 서비스 수. 누르면 가장 최근 판단의 상세.
- 주 영역: 서비스 표. 열: 상태, 서비스, 유입(req/s와 최근 60초 추이 선), 지연(설정 분위수의 값과 여유 막대. 목표는 툴팁), 성공률, 배치(장치 이름. 넘치면 "+n"), 자동 제어.
  - 상태 구간 선택: 확인 필요, 가동, 유휴, 전체. 기본은 확인 필요와 가동이며 유휴는 개수만 보인다.
  - 행을 누르면 서비스 상세로 간다. 이름순이며 값이 바뀌어도 순서를 바꾸지 않는다.
  - 상태와 지연은 서버가 계산한 최근 구간 값(실시간 지표의 `slo`)을 쓴다. 값이 없으면 "—".
- 보조 영역
  - 진행 중: 변경 작업, 예약, 측정 중인 장치, 실행 중인 실험. 누르면 해당 화면.
  - 최근 변경: 구성을 바꾼 판단, 실패한 작업, 설정 변경. 클러스터 사건은 개수와 링크만 둔다. 누르면 스케줄러의 해당 기록.
- 자료: 실시간 스트림(구성, 초당 지표, 사건), `v1/scheduler/state?view=summary`, `v1/observations/events`, `v1/observations/scheduler?filter=settings`, `v1/evaluations/active`.

### 7.2 서비스

목록 `/services`

- 표. 열: 상태, 서비스, 모델, 목표(분위수와 지연), 접수, 자동 제어, 변경 작업(진행 중인 서비스가 있을 때만). 검색과 상태 구간 선택.
- 주 동작: 서비스 등록.
- 자료: `v1/workloads?view=summary`, `v1/scheduler/settings`.

상세 `/services/[name]`

- 머리글: 이름, 준비 상태, 접수 상태, 자동 제어 스위치. 주 동작: 수정. 더보기: 삭제, 원본 보기.
- 현황 탭: 타일(유입, 지연과 목표, 성공률과 완료 수, 실패 수, 대기). 접속 이후 최근 5분의 유입과 지연 시계열. 배치 표(장치, 전력 모드, 분배 비율, 처리 중, 대기, 상태).
  - 배치 표의 동작 "분배 수정": 대화상자에서 인스턴스별 가중치를 바꾸거나, 새 요청을 막거나, 기본 분배로 되돌린다. 사유를 받는다.
- 요청 탭: 구간, 결과 종류, 적용 정의(둘 이상일 때) 선택. 요약 줄(서버가 준 결과별 건수, 설정 분위수 지연과 목표). 요청 표(시각, 결과, 소요 시간, 장치, 배치). 행 미리보기에 단계별 시간 막대. 내려받기.
- 정의 탭: 정의 목록(모델, 전처리기, 데이터셋, 목표, 과부하 정책, 대기 상한, 최종 기한), 적용 상태, 변경 이력 표.
- 테스트 탭: 입력 폼, 응답 대기 시간, 전송. 결과와 단계별 시간. 한 번만 보내고 자동으로 다시 보내지 않는다.
- 자동 제어 스위치는 스케줄러 설정을 조회한 버전 조건으로 고쳐 쓴다. 충돌하면 알리고 다시 보내지 않는다.
- 삭제된 서비스는 주소의 `?uid=`로 요청 탭과 정의 탭만 읽기 전용으로 본다.
- 자료: `v1/workloads/{name}`, 실시간 스트림, `v1/pools`, `v1/observations/workloads/{uid}`, `v1/scheduler/settings`, `v1/scheduler/operations`, `v1/workloads/{name}/infer`.

등록과 수정

- 한 페이지 폼. 구획: 이름, 모델, 전처리기, 데이터셋, 응답 목표, 과부하 정책. 오른쪽에 입력 요약. 아래 줄에 검토와 제출.
- 수정은 변경 전후를 검토 대화상자에 보인다. 조회한 버전을 조건으로 보낸다.
- 자료: `v1/workloads`, `v1/models`, `v1/preprocessors`, `v1/datasets`.

### 7.3 장치

질문: 어느 장치가 무엇을 실행하고 전력을 얼마나 쓰는가.

목록 `/devices`

- 타일: 전체 풀 W, 활성 풀 W, 선택 구간 에너지 J(서버 적분 값), 준비된 장치 수.
- 전체 전력 시계열과 구간 선택(15분, 1시간, 직접 선택. 최대 1시간).
- 표. 열: 장치, 종류, 역할(서비스, 측정, 가용, 제외), 준비, 전력 모드, 전력(W와 막대), 서비스.
- 자료: 실시간 스트림, `v1/pools`, `v1/inventory`, `v1/scheduler/state?view=summary`, `v1/scheduler/settings`(제외 장치), `v1/observations/power`(구간 묶음과 구간 합계).

상세 `/devices/[name]`

- 머리글: 이름, 준비, 역할. 주 동작: "계획에서 제외" 또는 "계획에 복귀". 스케줄러 설정의 제외 장치를 바꾸며, 검토 대화상자가 이 장치에서 실행 중인 서비스를 보인다.
- 타일: 현재 전력, 전력 모드, 인스턴스 수.
- 탭: 현황(전력 시계열, 인스턴스 표: 서비스, 분배 비율, 처리 중, 대기), 전력(구간 선택, 구간 에너지와 평균 전력, 공백), 사양(종류, 아키텍처, 메모리, 가속기, 전력 모드 표).
- 자료: 실시간 스트림, `v1/inventory`, `v1/pools`, `v1/scheduler/state?view=summary`, `v1/scheduler/settings`, `v1/observations/power`.

### 7.4 스케줄러

판단 `/scheduler/decisions`

질문: 스케줄러가 무엇을 왜 결정했고, 판단 주기를 지키는가.

- 타일: 마지막 판단 시각, 설정된 판단 주기, 마지막 판단의 소요 시간.
- 왼쪽 목록. 열: 시각, 결과(유지, 변경), 사유, 소요(판단 주기에 대한 막대. 주기를 넘으면 `--fail`). 선택: 변경만(기본) 또는 전체, 서비스, 구간. 내려받기.
- 오른쪽 상세(목록에서 고른 판단). 구획: 요약(결과, 사유), 후보 비교(유지안과 변경안의 예상 에너지, 서비스별 예상 지연과 목표), 서비스별 자동 제어 상태, 입력 수요, 용량 근거, 소요 시간 내역. 더보기: 원본 보기.
- 두 판단 비교: 목록에서 둘을 고르면 비교 대화상자가 항목별 차이를 보인다.
- 자료: `v1/observations/scheduler`(요약 보기, `filter=decision` 또는 `filter=decision-change`, `uid`, 단건), `v1/scheduler/settings`, `v1/scheduler/capacity`(가장 최근 판단), `v1/workloads?view=summary`.

작업 `/scheduler/actions`

질문: 무엇이 바뀌고 있고 무엇이 실패했는가.

- 종류 구간 선택: 작업, 예약, 사건.
- 작업 표. 열: 시작, 동작, 장치, 서비스, 상태, 소요. 진행 중인 작업이 위에 있다. 행 미리보기: 계획과 실제, 오류. 내려받기.
- 예약 표. 열: 서비스, 장치 수, 사유.
- 사건 표. 열: 시각, 종류, 대상, 내용. 이전 기록 더 보기.
- 자료: `v1/observations/scheduler?filter=action`, `v1/scheduler/state?view=summary`, 실시간 스트림(예약), `v1/observations/events`.

설정 `/scheduler/settings`

- 왼쪽 묶음 탭: 대상(자동 제어 서비스, 최소 수요, 제외 장치, 우선순위), 판단 주기(관측 구간, 판단 주기, 에너지 비교 기간, 전환 예비 비율, 하강 여유), 자원 한도, 자동 조정 항목(스위치 일곱), 용량 계산, 탐색(스케줄러 종류와 탐색 예산).
- 모든 값은 제자리에서 고친다. 고친 값에 표시가 붙고 아래 줄이 "변경 n건"과 "검토 후 적용"을 보인다. 검토 대화상자는 변경 전후 표를 보인다.
- 저장은 조회 때 받은 버전을 조건으로 보낸다. 충돌하면 최신 값과 내 변경을 나란히 보인다.
- 변경 이력: 머리글의 "변경 이력"이 최근 설정 변경 표를 서랍으로 연다.
- 자료: `v1/scheduler/settings`(조회, 저장), `v1/workloads?view=summary`, `v1/pools`, `v1/observations/scheduler?filter=settings`.

### 7.5 측정

범위 `/measurements/coverage`

질문: 어떤 조합이 측정되어 쓸 수 있는가.

- 요약 줄: 서버 요약 값만 쓴다(지원 조합, 측정 완료, 기준 충족, 실패). 기준 시각. "다음 조치 n"을 누르면 서버가 준 다음 조치 목록이 열린다.
- 선택: 모델(구간 선택), 장치 종류, 상태.
- 행렬: 행은 장치 종류와 전력 모드, 열은 실행 경로. 칸은 상태 점과 측정된 배치 수.
- 칸 미리보기: 상태, 사용 여부, 배치별 결과 표(배치, 지연, 건당 에너지), 분배 점유시간 상태, 실패 사유. 동작: "이 조건으로 측정 요청", "분배 점유시간 측정 요청", "요청 기록".
- 자료: `v1/namespaces/{ns}/measurement-coverage`, `v1/inventory`, `v1/scheduler/profiles`, `v1/namespaces/{ns}/profiling-runs`.

요청 `/measurements/requests`

- 표. 열: 요청, 모델, 장치와 전력 모드, 실행 경로, 상태, 완료 회차, 생성. 상태 구간 선택과 검색(전체 목록을 불러와 거른다).
- 주 동작: 측정 요청.
- 자료: `v1/namespaces/{ns}/batch-energy-optimizations`.

요청 상세 `/measurements/requests/[name]`

- 머리글: 이름, 상태. 실패하면 원인 한 줄. 주 동작: 같은 조건으로 요청. 더보기: 삭제, 요청 문서 내려받기, 원본 보기.
- 탭: 결과(배치별 표와 CSV, "같은 대상 결과" 링크), 회차(표. 행을 누르면 회차 상세), 조건(목록), 실패(실패했을 때만 있고 먼저 열린다. 원인, 종료 코드, 연결 회차).
- 삭제는 근거 파일까지 영구히 지운다는 확인을 받는다. 측정 중에는 막는다.
- 자료: `v1/namespaces/{ns}/batch-energy-optimizations/{name}/result`, `v1/namespaces/{ns}/profiling-runs?parentUID=`.

회차 상세 `/measurements/runs/[name]`

- 타일: 처리량, 지연 분위수, 평균 전력. 조건 목록. 배치 실행 표. 실패하면 마지막 오류 줄. 전체 로그는 더보기의 원본 보기.
- 자료: `v1/namespaces/{ns}/profiling-runs?q=`, `v1/namespaces/{ns}/profiling-runs/{name}/evidence-passport`.

요청 작성 `/measurements/requests/new`

- 종류 선택: 프로파일, 분배 점유시간. 방법 선택: 폼, 문서 가져오기.
- 프로파일 폼은 세 단계: 대상(서비스, 장치, 실행 경로, 전력 모드), 조건(측정 방식 값. 고급 값은 접힘), 검토(사전 검사 결과와 제출).
- 분배 점유시간 폼은 한 단계: 측정된 조합, 서비스, 배치, 이름. 검사 뒤 제출.
- 범위 화면의 칸에서 오면 대상이 채워져 있다. 주소로 들어와도 자동으로 제출하지 않는다.
- 자료: `v1/models`, `v1/workloads?view=summary`, `v1/preprocessors`, `v1/datasets`, `v1/inventory`, `v1/model-compatibility`, `v1/namespaces/{ns}/batch-energy-optimizations`(검사, 사전 검사, 제출), `v1/namespaces/{ns}/dispatch-occupancy-measurements`(검사, 제출).

결과 `/measurements/results`

- 종류 구간 선택: 처리 성능, 전환 비용, 분배 점유시간.
- 처리 성능 표. 열: 모델, 장치와 조건, 대표 배치, 지연, 건당 에너지, 사용 여부, 품질. 미리보기: 배치별 표(지연, 표본 수, 총 에너지와 추가 에너지, 유휴 전력과 실행 전력, 신뢰 구간), 조건, 측정일.
- 전환 비용 표. 열: 모델, 장치, 동작, 시간, 에너지, 표본 수, 상태. 통계는 서버가 준 값만 쓴다. 미리보기: 동작별 실측 값.
- 분배 점유시간 표. 열: 측정, 장치, 서비스, 배치, 점유시간, 상태. 미리보기: 분포와 조건. 행 메뉴: 삭제.
- 자료: `v1/scheduler/profiles`, `v1/namespaces/{ns}/operation-cost-measurements`, `v1/namespaces/{ns}/dispatch-occupancy-measurements`.

### 7.6 실험

실행 `/experiments/runs`

- 실행 중인 실험이 있으면 위에 진행 카드(단계, 경과, 남은 시간).
- 표. 열: 이름, 상태, 단계, 시작, 종료, 정리, 결과(게시 결과로 가는 링크).
- 주 동작: 새 실험.
- 자료: `v1/evaluations`, `v1/evaluations/active`.

실행 상세 `/experiments/runs/[name]`

- 머리글: 이름, 상태, 판정. 주 동작: 결과 보기(게시된 경우). 더보기: 수정(시작 전), 다시 실행, 중지 또는 삭제, 원본 보기.
- 탭: 진행(절차 단계, 현재 단계의 구간 경계와 부하 작업, 장애 주입, 잠정 결과), 계획(단계와 부하 표, 설정 변경), 정리(풀 반환 상태와 반환 확인 요청), 대상(구성요소, 준비, 이미지의 짧은 표기).
- 자료: `v1/evaluations/{name}`, `v1/evaluations/active`, `v1/evaluations/load-scenarios`, `v1/experiments/{id}`.

결과 목록 `/experiments/results`

- 표. 열: 실험, 기간, 판정(실행, 측정, 정리), 단계 수. 한 쪽에 다섯 건. 읽을 수 없는 게시가 있으면 개수를 보인다.
- 자료: `v1/experiments`.

결과 상세 `/experiments/results/[id]`

질문: 이 실험에서 어느 쪽이 나았는가.

- 머리글: 이름, 게시 판정. 그 아래 결론 줄: 비교 상태(동일 조건, 참고, 기록 없음), 에너지 차이(J와 %), 목표를 못 지킨 서비스. 주 동작: 다시 실행.
- 단계 선택. 비교 쌍이 있으면 기준 단계 선택.
- 탭: 요약(서비스별 카드: 판정, 기한 내 성공률, 유효 처리량, 지연 분위수. 에너지와 평균 전력. 비교 쌍이 있으면 차이 값), 구간(단계와 부하 구간별 요청률, 지연, 에너지 막대. 구간별 성공률과 가장 나쁜 구간 표시. 같은 기간의 스케줄러 기록 링크), 요청 결과(서비스별 결과 분류와 대기, 거절 표), 에너지(노드별 계측 표), 조건(비교 조건, 측정 규칙, 정의 출처).
- 자료: `v1/experiments/{id}`, `v1/evaluations/{name}`.

작성 `/experiments/runs/new`

- 구획 탭: 기본(이름, 질문, 부하 발생 장치), 단계(단계 목록. 단계마다 부하 시나리오와 설정 변경), 비교, 판정 기준. 오른쪽에 사전 점검 결과와 제출.
- 시작점: 빈 양식, 기존 실행 복사, 게시 결과 복사.
- 더보기의 "원문 편집"이 정의 전체를 JSON으로 고치게 한다.
- 자료: `v1/evaluations/template`, `v1/evaluations/load-scenarios`, `v1/evaluations/preflight`, `v1/evaluations`, `v1/experiments`, `v1/inventory`.

부하 시나리오 `/experiments/scenarios`

- 표. 열: 이름, 구간 수, 전체 길이, 서비스, 사용 중, 생성. 주 동작: 새 시나리오.
- 상세: 요청률 미리보기 차트, 구간 표, 서비스별 입력. 주 동작: 수정. 더보기: 복사, 삭제, 원본 보기.
- 작성 폼: 이름, 구간 표(길이, 서비스별 요청률), 도착 분포, 서비스별 입력(데이터셋, 기록 입력, 난수 씨앗). 저장 전에 사전 점검을 거친다.
- 자료: `v1/evaluations/load-scenarios`, `v1/evaluations/load-scenarios/preflight`, `v1/evaluations/inputs`, `v1/workloads?view=summary`, `v1/datasets`.

### 7.7 카탈로그

목록 `/catalog/[kind]`

- 표. 열: 이름, 요약(모델은 파일 형식과 실행 경로 수, 전처리기는 입출력, 데이터셋은 필드), 사용하는 서비스 수.
- 주 동작: 등록.
- 자료: `v1/models`, `v1/preprocessors`, `v1/datasets`, `v1/workloads?view=summary`.

상세 `/catalog/[kind]/[name]`

- 머리글: 이름. 주 동작: 수정. 더보기: 삭제, 등록 문서 내려받기, 원본 보기.
- 정의 목록과 표(모델은 파일과 실행 경로). 사용하는 서비스 표. 사용하는 서비스가 있으면 삭제 확인이 그 목록을 보이고 삭제를 막는다.

등록과 수정

- 한 페이지 폼과 "문서 가져오기" 탭(YAML 또는 JSON). 반복 항목(파일, 실행 경로, 필드)은 추가와 삭제가 되는 행 편집기.

## 8. 서버 확장

화면에 필요한 값을 서버가 주지 않을 때만, 기존 관례대로 더한다.

| 확장 | 이유 |
|---|---|
| 실시간 지표의 서비스별 `slo`: 최근 구간의 표본 수, 목표 이내 수, 설정 분위수 지연, 충족 여부 | 개요와 서비스 화면이 설정 분위수 지연과 충족 판정을 서버 값으로 보인다. 기존 지표는 초 단위 p50, p90, p95, p99뿐이다 |
| `v1/observations/scheduler`의 `filter=decision-change`: 구성을 바꾼 판단만 | 10초마다 쌓이는 유지 판단 사이에서 변경을 찾는다 |
| `v1/observations/scheduler` 요약 보기의 판단 행에 `reasons`, `targetKeep`, `evaluationElapsedNanos`, `keepExpectedJoules`, `targetExpectedJoules` | 판단 목록이 행마다 큰 기록을 다시 읽지 않고 사유, 유지와 변경, 소요 시간, 예상 에너지 차이를 보인다. 차이는 브라우저가 두 값을 뺀다 |
| `v1/observations/scheduler` 요약 보기의 작업 행에 `workloadUID`, `workloadUIDs` | 작업 기록이 어느 서비스의 작업인지 보인다 |
| `v1/observations/workloads/{uid}`의 `order=desc` | 서비스 요청 목록이 가장 최근 요청부터 보인다. 여러 쪽을 읽을 때는 구간 끝을 고정한다 |

## 9. 개발과 확인

- Node 24를 쓴다.
- 재생 서버(`pnpm replay`)가 저장해 둔 ChillServer 응답과 실시간 스트림을 재생한다. 실제 클러스터를 바꾸지 않는다.
- 재생 장면 둘: 저장 당시 상태(토큰 `captured`), 서비스가 실행 중인 합성 상태(토큰 `active`).
- 화면마다 두 장면, 밝은 테마와 어두운 테마, 1440px와 390px 너비에서 확인한다.
- 웹 표준 점검: Modern Web Guidance 스킬(`npx -y modern-web-guidance@latest search|retrieve`)의 안내와 대조한다. 대상은 공용 부품과 화면의 HTML 구조, 접근성, 폼, 대화상자와 팝오버, 표, 반응형 배치, 성능이다. 기준은 Baseline 2024이며 `chill-dashboard/AGENTS.md`에 적는다.
