# 연구 목표와 판단 기준

## 최종 목표

CHILL은 서로 다른 워크로드를 같은 서빙 경로로 동시에 운영한다. 실측 근거가 있는 노드 후보에서 첫 구성을 자동 생성하고 부하에 따라 주기적으로 재구성한다. 워크로드별 서비스 수준 목표(Service Level Objective, SLO)를 우선 만족시키고 전환을 포함한 전체 자원 풀의 에너지를 최소화한다.

연구의 완료 기준은 [근원 명세와 평가 시나리오 7개](../spec/README.md)다. mobilenet 영상 분류, SmolVLM2 시각 질의응답과 PLC 이상 탐지가 같은 경로에서 동작해야 한다. 측정 완료 수, 배포 성공과 시연 성공은 연구 평가 완료와 따로 보고한다.

## 유지할 설계 방향

- 원시 요청 → 워크로드별 큐 → 배치 → 전처리 → 추론 → 후처리 → 요청별 응답을 공통 경로로 유지한다. 입력 계약 검사는 분배 전에 수행하고 단계별 경과 시간을 남긴다.
- 후보와 용량, 전환 비용은 측정 근거에 연결한다. 특정 모델이나 노드 이름에 맞춘 추정값과 예외 분기를 추가하지 않는다.
- 첫 구성은 수동 부트스트랩 없이 생성한다. 운영자의 최소 수요는 스케줄러 설정으로 명시하고 실행 기록에 고정한다.
- 실물 자원은 Pod 기준 장부로 관리한다. 관측 실패는 상태의 불확실성으로 남기고 실물 소실로 해석하지 않는다. 작업은 영향 범위를 예약하며 그 밖의 자원은 계속 판단한다.
- 수요 증가에 대한 배분과 확장은 빠르게 수행한다. 축소와 에너지 목적 교체는 안정화 기간을 거친다. 에너지 비교 기간은 후보에 독립적인 설정값으로 유지한다.
- 계수와 계산된 측정 조건, 입력 근거 식별자 및 제어 설정은 실행 기록에 고정한다. 측정의 signed 원시 값과 운영 정책 투영을 구분한다.

세부 계약은 [스케줄러 SRS](../spec/scheduler/SRS.md), [측정 설계](../design/serving/measurement-api.md), [구성 선택](../design/serving/analytic-planner.md), [실행 설계 §5.4](../design/serving/scheduler-implementation.md)에 둔다.

## 현재 우선순위와 범위

현재 E5 결과는 [확정 보고서](../reports/e5-evaluation-20261030.md)에 있다. 실행 상태와 다음 우선순위는 [인수인계](../handoff.md), 미해결 post-E5 과제는 [남은 로드맵](../plans/2026-10-26-remaining-roadmap.md)을 따른다. 시연·측정·화면 수용을 연구 평가 PASS와 구분한다.

연구 한계는 결과에 남긴다. 프로파일과 서빙의 체계적 차이, legacy 측정의 미재인증, 전력 결측, 전환 중 실패와 비교의 통계적 보장 범위를 숨기지 않는다. 새 보정 정책과 추가 최적화는 직접 차단을 해소하는 근거와 승인이 있을 때 다룬다.

## 단계 점검 다섯 질문

1. 지금 작업은 최종 연구 목표와 다음 실제 클러스터 검증에 직접 기여하는가?
2. [사용자 의도](user-intent.md), [핵심 결정 일지](decision-log.md)와 현재 SRS 및 설계에 맞는가?
3. 범위가 불어나거나 불필요한 장치가 생겼는가? 기존 경로로 해결하거나 삭제할 수 있는가?
4. 다음 단계의 의존성과 우선순위가 실제 관측에 맞는가?
5. 새 조건, 판정이나 범위 중 사용자 결정이 필요한 것은 무엇인가?

단계 전환, 실패에 따른 우회, 승인 요청 직전과 긴 실행 중간에 실제 근거를 읽고 답한다. 확인하지 않은 검사와 실행하지 않은 작업은 완료로 기록하지 않는다.
